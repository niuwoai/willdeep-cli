# 评测与 RSI 产品模块

> 范围：智能体 RSI、可靠性与模型评测、用量/反馈账本、派工指标，以及这些证据允许和不允许得出的结论。开发版本见[产品概览](../../PRODUCT_OVERVIEW.md)。本页不重新计算历史实验结果。

## 能力概要与用户入口

WillDeep 将真实付费实验、免费离线回放、工程回归和日常遥测分开保存。CLI `willdeep agents rsi` 与 Web 智能体实验区管理候选和实验；模型/可靠性评测脚本、用量与反馈命令、`agent-metrics` 提供不同口径的数据。任何候选晋升、生产迁移、付费调用或上传都需要各自门禁和授权，不能由“已有账本”自动推出。

## 已实现范围

### RSI 候选与实验隔离

- P4a/P4b 支持从已安装基线登记独立候选、冻结 suite/split/fixture/verifier、双臂配对执行、断点恢复、不可覆盖证据和按账号隔离的本机目录。候选不会修改当前安装，也不会自动激活、同步、晋升或发布。
- 每题、每臂、重复和尝试使用独立 workspace/home/反馈/事件；通用离线入口只允许确定性 Mock 与只读 reviewer。真实模型、付费预算或未登记路由在没有单独批准时明确拒绝。
- Web 实验备注只是按账号隔离的本机显示信息，不改 revision、实验契约或评分；登录、定义同步和本地 `local-only` 标记都不构成上传授权。上传需当前账号的单独有效 grant，并在 HTTP 前后复核账号；摘要不含题目、源码、路径、命令或输出正文。
- `offline_pipeline_passed` 只证明工程流水线，`quality_improvement_claimed` 与 `official_promotion_allowed` 保持 false。Mock、prefix verifier 或一端成绩不能替代真实模型质量、独立 oracle 或另一端验证。

### 已登记的真实实验与免费回放

- 2026-10-15 首轮独立批准真实实验记录 288 个计划终态：275 个可评分、13 个预算耗尽，708 个物理模型请求逐笔核账，累计实扣 **$0.667158**，低于当时批准的整批 $20 上限。Mac 与 Rust 配对差异的置信区间均含零，不支持候选晋升；格式失败不能解释为审查判断错误，未评测理由语义或泛化能力。
- 该付费授权只覆盖当时冻结模型、题量、预算与宿主，不延续为后续实验授权。报告中的价格、请求和样本是历史事实，不是当前账户报价或未来预算。
- 0.102.0-rc9 的免费格式回放只读取已保存回答：275 份可评分回答中有 79 份格式误拒恢复识别，原通过样本零退化；没有新模型请求、费用或原始首轮分数改写。事后解析改进不是独立质量提升证据。
- 0.103.0-rc1 的 P4b 免费工程补齐使用本地 Mock 与宿主固定夹具/参考函数：两端 8 个正常案例和 6 个资源边界通过，保留原 13 个预算终态与账本，新费用为零。它证明输出、预算停止、最小复现和证据链可运行，不证明候选更好。
- 新盲测目前只登记元数据方案；未来题目、oracle、seed、模型、账号价格、题量、请求/重试/token 上限和最大费用必须重新冻结、审计并取得批准。旧 24 题转为回归，不得冒充新的 holdout。

### 可靠性与模型评测

- 可靠性评测以 JSON 与 Markdown 同时报完成率、误报率、恢复率、耗时、Token 和人工介入；缺失指标保持未知，不补零。退出码 5 与结构化恢复信息只说明可恢复失败语义，不代表任务成功。
- 模型行为评测将离线会话指标、固定任务集、定期运行和趋势分层。固定任务运行冻结命令与工作目录证据，报告按模型/时间归档；未跑成的一轮保留失败目录和原因，`null` 指标不按 0 比较。
- SWE-bench 失败轨迹驱动的 Runtime 强化补齐测试入口、主子 Agent 截止/收尾、重复失败保护、异常补丁交付和恢复契约。机制回归通过不能宣称新的模型解决率；真实提升需要预注册的可复现实验。
- 自动压缩、检查点故障注入、重复错误收敛和真实 Provider 场景分别验证具体机制；一项局部通过不外推到全部模型、平台或长期任务。

### 用量、反馈与派工指标

- `willdeep.usage-ledger.v1` 对主回合、Worker、压缩及标题/预测/路由/判官/视觉兜底等辅助模型调用逐次记账，daemon 与进程内执行共用入口；只记计量与身份，不记正文。失败、取消和 Provider 缺失用量分别保留，宿主异常退出可标记不完整。
- `usage backfill` 只回填可从 Runtime 事件确定关联的历史，按 ID/事件序号/活动任务状态去重；账本上线前的进程内历史无法回填。账本存在不等于所有预算都已强制执行，也不能把未知用量补成零。
- 反馈账本记录下一句建议、工具结果、Worker 运行、目标结果和用户后续信号。健康报告只输出计数与 ID；运行错误可能没有收尾，工具成功率只覆盖已返回调用，旧账本缺字段时不能套用新分母。
- 纠正率、坏结局率和危害度使用运行时事实与有限词法启发式，报告明确来源和 unknown。它们是关联指标，不是因果结论；命令不会自动改提示词，候选晋升仍需设计门禁。
- `agent-metrics` 区分通过、失败与未验证，提供 Worker/档位实际运行、专家占比、Skill Coverage、Verified Success 和 Escalation 等快照。旧 `deep` 记录按历史兼容处理，不作为当前独立公开职责；维护者日常样本小且非受控，只看趋势不等同靶场对照。

## 当前限制

- 当前没有由 RSI 自动晋升、灰度、回滚或生产发布候选的闭环；服务端上传也只标记为 client-reported，不能替代本机原始证据。
- 真实评测的题目覆盖、评分格式和宿主环境有限；首轮结果不证明理由质量、泛化能力、生产收益或其他模型/平台等价。
- 日常账本可能存在旧版本缺字段、未知用量、不完整收尾和小样本；任何比例必须带分母、时间窗与来源，不把未知当成功。
- 本次产品文档拆分未重新运行模型、回放、付费请求或统计脚本，所列数字保持原报告的时间与授权范围。
