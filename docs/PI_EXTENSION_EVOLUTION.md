# 参照 Pi 的扩展能力演进

## 对照依据

Pi 的核心价值在于让扩展进入 Agent 生命周期，而不只是提供外部工具或页面。对照依据为 [Pi 扩展文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)（main 为滚动文档）。其中包括生命周期事件、工具注册、上下文变换、命令、UI、持久状态与重新加载。Pi 的 TypeScript 扩展在进程内执行，拥有宿主进程的系统权限。

我们的现有基础是共享插件包、Web 页面桥、隔离的 MCP 进程、Skills、宿主持久工作流与 shell Hooks。增强应复用这些入口和既有审批，逐步开放运行时能力。

## 能力对照和优先级

| 能力 | 当前基础 | 增强方向 |
|---|---|---|
| 自定义模型工具 | 插件 MCP 工具可进入聊天 | 复用 MCP 工具发现与现有权限链 |
| Agent 生命周期 | 原有工具前后与审批结果 Hooks | 首批增加运行前门禁与运行结束观察 |
| 动态上下文 | 项目规则、Skills、宿主动态上下文 | 后续设计带长度预算、来源标签和权限校验的上下文贡献协议 |
| 命令与界面 | 插件命令、Web 菜单、页面桥；CLI/TUI 自动注册 MCP 命令 | 已提供命名空间调用、命令列表和 JSON 对象参数；动态补全、表单后续完善 |
| 扩展状态 | 插件隔离存储与 Runtime 账本 | 后续定义会话级状态及分支、恢复时的归属 |
| 重新加载 | 插件版本与内容摘要审批 | 后续设计空闲边界原子切换；内容变化仍需重新校验审批 |
| 分发与开发体验 | 本地插件安装、共享 manifest | 后续补模板、契约校验及能力发现，远程分发单独设计 |

已实现生命周期事件及 CLI/TUI 扩展命令注册。命令复用清单中的 MCP handler、插件内容审批和隔离连接，以 `/plugin:<插件ID>:<命令ID>` 调用，参数为 JSON 对象；无 UI 的终端拒绝页面导航等 handler。用法和限制见 [插件系统](PLUGINS.md#cli--tui-扩展命令注册)。其余条目为演进方向，不表示已经实现或已排入执行任务。

## 首批生命周期契约

在既有 `[[hooks]]` 中增加两个事件，沿用 shell 命令从 stdin 接收有界 JSON 的协议：

- `before_agent`：在一次 Agent 运行的模型处理之前调用，可通过阻塞式 Hook 拒绝本次运行，用于工单、环境就绪等自定义前置检查。
- `agent_end`：在一次 Agent 运行返回时观察真实终态，用于审计与外部流程衔接。它不能改变已经形成的结果，也不表示所有后台任务均已完成。

事件应沿用宿主绑定的会话与工作区标识。生命周期事件不传完整提示词、会话历史、模型输出或原始错误内容。预算停止与错误不能记为成功；前置拒绝也要与成功结束区分。事件处理不获得额外的模型工具权限。只读委派继续禁止执行操作者配置的 Hook。

Hook 是受信任操作者配置的命令，沿用现有配置权限边界。它不是不可信插件页面注册任意命令的入口。未来若允许插件贡献 Hook，必须同时解决内容审批绑定、权限继承与进程隔离，不能直接把 manifest 字符串当作受信任 shell。

详细配置、终态字段与投递限制见 [Hooks](HOOKS.md)。事件在运行中的位置见 [Hooks 体系](CLI_HOOKS.md)。`sdk/hooks` 只描述这五条已投递事件，不注册进程内 TypeScript 扩展。

## 尚未完成的运行时能力

以下条目仍是设计与实现缺口，不能用已有页面桥、全局插件存储或按次发现替代验收：

- **动态上下文贡献**：定义插件贡献协议，在模型请求前接入；由宿主限定每插件及总长度预算，标注来源，校验启用状态、内容审批与所需权限。项目规则和页面 `getContext()` 不等于插件能向 Agent 贡献上下文；只读委派不得因此获得插件执行能力。
- **会话状态与恢复**：状态必须按插件及宿主绑定的会话隔离，明确分支的初始快照、后续写入归属和重启恢复规则。插件不能通过自报会话 ID 访问其他会话；现有全局设置与插件隔离存储不满足此项。
- **运行时原子重载**：在没有在途调用的空闲边界切换宿主快照与连接，重新检查内容审批；验证旧调用完成、新调用切换、审批失效和失败回退。刷新终端命令列表只更新发现结果，不代表运行中的 MCP 连接已热切换。
- **参数表单**：需要明确参数 schema 的来源、验证规则及各宿主支持范围；现有 JSON 对象输入和命令名补全不等于表单。

远程分发仍需单独设计来源、版本选择与审批绑定；本地模板与静态校验不包含插件市场、远程安装或自动发布。
