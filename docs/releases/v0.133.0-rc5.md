# v0.133.0-rc5

修复 Responses 接口 thinking 模式的工具续轮。0.129.0-rc3 只回传了有原文的 `reasoning_text`；MuchToken 的 `deepseek-v4-flash` 在 thinking 模式带 tools 时要求每一条 assistant 消息都带，缺一条整个请求返回 HTTP 400：`The reasoning_text in the thinking mode must be passed back to the API`。

缺的来源有两处：模型对 `git commit`、`git switch` 这类直给的步骤常常不吐思维链；上下文压缩会把带推理的工具批次替换成没有推理的摘要或归档引用。chat-completions 分支早有同样的补空（`reasoning_content: ""`），Responses 分支此前没有。

## 变更

- 历史里出现过非空思维链时，Responses 出站给每条 assistant 消息都带 `reasoning` / `content[].reasoning_text`，缺的补空串。流式与非流式共用同一段编码。
- 历史里从没见过思维链的端点不发这个项，严格校验未知项的上游不受影响。
- summary 仍不当原始推理回放；已经丢掉推理原文的既有会话不会凭空恢复，只有补空能保住的续轮才恢复。
