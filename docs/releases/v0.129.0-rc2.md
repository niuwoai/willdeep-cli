# v0.129.0-rc2：计划完成状态及时同步

日期：2026-10-29。

rc1 实测中，一个后台步骤已经完成，模型也收到结果，但卡片仍等待另一个步骤结束才一起更新。本版让完整步骤绑定实际后台作业 ID，Runtime 根据退出状态独立保存并推送 `plan_updated`，Web/TUI 原位刷新；模型等待、前台命令等待和后台等待期间都能同步。

依赖仍要求全部前置成功；非零退出或作业丢失不放行依赖，绑定只接受本会话的 shell 作业。重试使用新的作业 ID，旧通知不能完成新尝试；完整计划快照省略绑定或状态时仍保留真实执行结果。只有代表完整步骤的命令才绑定，部分工作不能被误报成整步完成。

## 本机真实验收

使用已安装的 `willdeep 0.129.0-rc2`、真实 some.im / deepseek-v4-flash 和内嵌 Web，在独立临时工作区运行三个计时命令，没有手工更新计划或任务结果。HTTP 响应头 `X-App-Version` 为 `0.129.0-rc2`。

| 步骤 | 开始 UTC | 结束 UTC |
| --- | --- | --- |
| A | 05:42:28.039137 | 05:42:58.040826 |
| B | 05:42:28.090346 | 05:43:43.092289 |
| C | 05:44:09.520833 | 05:44:12.522366 |

- A/B 启动差 0.051209 秒，实际重叠 29.950480 秒，卡片同时显示两项进行中。
- A 完成后 0.270095 秒观察到持久化计划变为 A=done、B=in_progress、C=pending。对应界面截图显示一项进行中、C 只等待 B；当时前台 `sleep 15` 尚未返回，不需要等模型继续回复。
- C 在两项前置成功后启动，晚于 B 完成 26.428544 秒；启动仍经过模型调度，本版没有承诺依赖解除后零延迟启动。
- C 完成后独立刷新，最终卡片 3/3 完成。会话 ID：`caa4af34-afa4-5ec5-a792-a6fff3b21f27`。

0.270095 秒是 50 ms 只读观察器测得的持久化延迟，不是浏览器绘制耗时。视觉验收使用内嵌 Web；原生 TUI 通过针对性测试覆盖，没有另做 TUI 视觉验收。完整 JSON、Markdown、任务脚本及截图保留在本机 `target/verification/0.129.0-rc2-live/`（不提交凭据或用户运行数据）。
