# v0.134.0-rc1

分凉出来的会话现在记下来源，Web 和 TUI 都按谱系显示。WillDeep 里会话只会由分凉产生另一条会话（Web 的分凉按钮、TUI 的 `/fork`、控制面 `session.fork`），所以文案是「分凉自」，不是「由模型发起」。

## 变更

- 分凉时服务端把 `started_by` 写成源会话 ID，核心会话文件和 Runtime 会话记录各存一份。请求体没有这个字段，客户端不能自己指定来源。再分凉一次只指向直接来源，不继承祖父。
- Web 与 TUI 的会话列表把分凉会话缩进在来源正下方，左侧一条竖线连起来；对话标题下显示「分凉自「来源」· 多久前」，时间按分凉会话自己的创建时间算。来源不在当前这份列表里（别的工作区、已归档、被过滤掉或已删除）、两条互相指向、或指向自己时，它仍作为普通会话留在原位，不隐藏。
- 这个字段不进执行指纹：后写的执行快照不会把已经记下的来源抹掉。独立执行通道的快照不带来源。
- `willdeep session` 的列表、查询和搜索输出在行尾追加 `parent=<uuid 或 none>`，不插入到已有列之间。
- 旧会话文件和旧版 Runtime 都不带这个字段，读出来为空，列表不会因此少一条。Runtime Session 的 schema 仍是 2，不加号。
