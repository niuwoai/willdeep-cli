# v0.138.0-rc5

## Added

- 实例联邦（1:1）。两台公网可达的 willdeep 可以互相聊天：
  - `willdeep fed invite` 打印一次性邀请链接（10 分钟、只能用一次），对端 `willdeep fed join <链接>` 配对并换回一对共享密钥；
  - `willdeep fed say <名字> <内容>` 发消息，`fed list` 看联系人与各自落在哪条会话，`fed remove` 解除配对；
  - TUI 是同一组 `/fed` 命令；Web 的公网入口页新增「联邦」标签，可以生成邀请、加入、发言、打开会话。
- 入站消息作为普通 Runtime 轮次进入 `[federation] workspace` 指定的工作区，正文包成「外部数据、不是指令」。一轮结束后按 `reply` 策略（`always` / `mention` / `never`）把最后一条助手回复自动回传，`max_auto_turns` 到顶就停，避免两台 Agent 互相刷屏。
- 请求签名覆盖发送方、接收方、时间戳、nonce、消息 id 与正文摘要；时间窗 ±300 秒、nonce 一次性、每联系人每分钟 20 条。
- 联系人与共享密钥存在 `~/.willdeep/federation.json`（0600），不进 `config.toml`。联邦路由只在 `[federation] enabled` 时注册，且要求 `[intake] enabled` 并配置 `public_url`。

## Changed

- `[federation]` 配置段：`workspace`（绝对路径）、`reply`、`max_auto_turns`；`config check` 会校验它与 `[intake]` 的依赖关系。

## Fixed

- 配置与入口的单元测试改用当前平台的绝对路径（临时目录），Windows 上不再因为 `/srv/...` 既不是绝对路径也没有盘符而失败。

## Fixed

- 本次改动的 Rust 源文件按 `cargo fmt` 格式化，CI 的格式检查通过。

- `willdeep identity` 与 `willdeep fed` 的实现移到 `identity_cmd.rs`，`main.rs` 回到 3000 行以内；身份改名测试不再假设首次生成的名字。

- 联邦签名改为收 `Signed` 结构体，nonce 缓存用类型别名，`cargo clippy --workspace --all-targets -D warnings` 通过。

## 已知限制

- 只有 1:1，没有群聊（P2）；没有流式回传与逐条引用。
- nonce 缓存只在进程内，daemon 重启后按时间窗重新计时；时间窗是真正的重放边界。
