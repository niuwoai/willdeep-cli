# v0.134.0-rc6

本版补三处显示。前两项是 TUI 的，第三项是 Web 的。

## 变更

- TUI 在一轮还在跑时按 Enter 发出的消息立即回显。此前它只进 Runtime 队列并清空输入框，聊天区要等这一轮结束、下一轮任务启动才写出这句，长轮次里要等好几分钟；向上箭头的历史输入只读会话文件，落盘前同样找不到。回显是聊天记录里的一行，简洁模式不碰它；下一轮任务启动时补发的事件认领已有的回显，不会再写一行。这条消息在队列里被删除或改掉、还没轮到发送时，回显行改成「未发送」。暂缓提交（Cmd+Enter、`/queue add`）不变，仍显示在待发队列里。
- TUI 在压缩期间把状态挂到触发它的那条用户消息正下方。压缩发生在「轮次开始」之后、正文之前，长则数十秒，期间聊天区一行都不长。现在那句下面显示「正在压缩上下文」并读秒，压完同一行换成「上下文已压缩」，正文、思维链、工具或计划卡片任一出现就整行撤掉。这行不进记录，重开会话不会留下；活动区原有的压缩进度照旧保留。
- Web 聊天区补上与 TUI 同一层的简洁显示。简洁是默认，此前 Web 只有提示词侧的简洁，每一段中途文字仍各自占一个气泡。现在干活时只留最近一段，摆在一行会替换的状态上，后面跟着这一段已显示的时长，下一段来了就整行换掉；轮次收尾才落成正文。正文就是它时只落一次，前面拼了提示时两段都留，被截断的状态行是正文前缀时不再单独落一段。轮次被中断或请求失败时，还挂在状态行上的最后一段补写进聊天区。计划围栏两种模式都原位更新卡片。重开会话或轮询刷新时按同样的规则回放，带工具调用的记录保留，工具调用仍收进「N 次工具调用」那一行。这只是显示层的取舍，会话记录一个字不删。`/verbose` 切回逐段显示。

CLI、Runtime SDK、内嵌 Web、npm 清单统一为 `0.134.0-rc6`；服务端继续通过现有 `X-App-Version` 与健康接口暴露版本。
