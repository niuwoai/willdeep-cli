# v0.139.0-rc5

## Added

- 首屏吉祥物：一只真彩色的深潜鲸，下面是产品名与版本号。鲸鱼和产品名都取自同一份像素网格，进 transcript 的是纯文本行，所以拖选、复制、搜索拿到的就是屏幕上看到的字；聊天区窄于 24 列时换成 12 列的小号（行数不变，选区和行号不会错位），终端设了 `NO_COLOR` 或 `TERM=dumb` 时退回单色，形状不变。
- 聊天区拖选松手即复制：选中的文字直接写进剪贴板，状态行提示「已复制 N 字到剪贴板」。想只拖选看看、不覆盖剪贴板里已有的内容，把 `[ui] copy_on_select` 设成 `false`，复制改回 `Cmd/Ctrl+C` 或 `Y`。

## Fixed

- 首屏真的能看见了。rc4 修的是「要不要补欢迎语」的判断，可补上之后，启动流程末尾又从 daemon 拿了一份 display session 整体替换聊天记录——空会话也返回成功，于是小鲸鱼、产品名、版本号和问候语连同启动提示一起被清空，屏幕仍是白的。现在所有「换一份记录」的路径都走同一个装载入口（`load_transcript`），先装载再补首屏，并且排在启动提示之前，顺序不会再被后来的整体赋值打乱。
- 空白首屏也会给欢迎语。判断「要不要放首屏」原来只看记录列表空不空，可列表可能只剩空白行，或者内容全是关掉的思考行——列表非空、屏幕全白，用户进来以为程序没起来。现在按「屏幕上有没有一条看得见的内容」判断，简洁 UI 与完整 UI 一视同仁；`/clear` 之后也重新画首屏。
- Web 的模型选择器与审批档位面板选完就收起，成功提示改在输入框上方常驻 4 秒。以前提示画在面板里，面板开着才看得见；选完既不关弹窗也没有面板外的反馈，看起来像没有生效。切换失败时面板保持摊开，错误原因留在原处。
- 验证判定不再把「并发改动」算成「测试失败」。检查命令退出码 0、但运行期间工作区被别的会话或进程改动时，这条结果对起始和结束两个快照都不是证据；以前统一记成 `failed`，提示也像在说测试挂了，模型只能一遍遍重跑，最后以「缺少验证记录」收尾。现在单独记为 `invalidated`：提示明说「不是测试失败、可能有其他进程或会话在写、等工作区稳定后重跑一次」，反馈账本记 `stale` 而不是 `failed`；同一条命令另有一次真实失败时仍按失败报告。审计汇总单列「失效」，Diff 面板标黄；结束复核快照也留给审计面看。`invalidated` 仍然不能通过完成门禁。
- 「配置版本」不再是自由整数框，只列运行时认识的 `1`；写别的值会在保存前被拒，不会落盘一个下次启动就报错的版本号。
- 配置页认识 `[intake]`：公网入口的 `enabled`、`listen`、`public_url` 直接出现在设置页，不再落进「未收录的配置项」。
- `listen` 必须是 `IP:PORT`，`public_url` 必须是 http(s) origin（可带单个尾部斜杠，不带路径、查询、片段或凭据）；格式不对会在保存前被拒，不会写出一个下次启动就加载失败的配置。
- 实例联邦开启（`[federation] enabled = true`）时，配置页不允许关掉 `[intake] enabled` 或清空 `public_url`，与 `config check` 的依赖校验保持一致。
- 站点、表单和 webhook 的数组表仍由 Web 的「公网入口」页维护；配置页把它们保留为只读展示，不会改动。
