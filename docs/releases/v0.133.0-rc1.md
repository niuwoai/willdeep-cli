# v0.133.0-rc1

本版把出站通知从单条 webhook 扩展为多渠道（webhook / 飞书 / 邮件），并包含原计划
随 0.132.0-rc2 发布的两处修复。

## 新增

- `[notifications]` 新增 `[[notifications.channels]]`：可追加任意条渠道，每条渠道
  用自己的 `events` 过滤事件，失败只记自己那一条错误。原有 `webhook_*` 四个键继续
  有效，等价于一条名为 `webhook` 的渠道；`[notifications]` 里的未知键仍然被忽略，
  与桌面端共用的配置格式不变。
- 飞书自定义机器人：文本消息，支持可选签名校验
  （`sign = base64(HMAC-SHA256(key = "{timestamp}\n{secret}", data = ""))`）；
  飞书业务错误也返回 HTTP 200，因此只有响应体 `code == 0` 才算送达。
- 邮件外发抽象成可插拔后端：SMTP（lettre，只启用 rustls 栈，不引入 OpenSSL）与
  Resend HTTP API。每个密钥位置都支持内联写在配置里，或只引用环境变量名，二选一：
  `secret` / `secret_env`、`password` / `password_env`、
  `api_key` / `api_key_env`。内联密钥要求 Unix 配置文件权限 `0600`，`willdeep config
  show` 统一替换为 `[REDACTED]`；环境变量缺失时只跳过该渠道并记录原因，不阻止启动。
  `tls = "none"` 且带凭据只允许回环主机。
- 飞书正文与邮件主题按 `[agent] language` 输出中/英/日文案；邮件主题压平换行并
  截断到 120 字符，防止会话标题里的换行变成 header 注入。
- `willdeep doctor` 的 `notifications` 项列出实际生效的渠道（不含端点与密钥），
  并报告被跳过的渠道和原因；完整配置说明见 `docs/NOTIFICATIONS.md`。

## 修复（原 0.132.0-rc2）

- TUI：可见的思考记录不再切断工具调用段。模型每调一次工具前都会落一段思考，此前
  每段工具行只剩一条，折叠规则永远不会生效；现在按「工具行 + 夹在中间的思考行」
  归段，收起时只收工具行，最新一段保留汇总行与最新一条工具调用，思考记录原样留在
  原处。`/tools` 仍展开全部工具行，原始会话记录不变。
- Web：回环监听（本机打开）时，工作区选择器列出 Runtime 注册表里所有仍然存在的
  已注册工作区，不再只显示启动时 `--web-workspace` / `--workspace` / `--project`
  指定的目录。选择工作区后，会话列表、定时任务和插件文件边界与选择器共用同一份
  名单；已经不存在的注册目录不显示。对外暴露（非回环）的实例仍严格只认启动参数
  给出的白名单。

## 验证

- 通知：`cargo test -p willdeep --bin willdeep notify` 覆盖 webhook / 飞书 / Resend
  三渠道同时收到同一事件、单条渠道失败不拖累其余、签名是原始请求体的 HMAC、每条
  渠道独立的事件过滤、缺失密钥只跳过该渠道、飞书 HTTP 200 业务错误判失败、Resend
  200 但无 `id` 判失败、RFC 2047 主题与 header 注入防护。
- 配置：`cargo test -p willdeep --bin willdeep config::` 覆盖四种渠道写法的解析与
  校验、smtp/resend 二选一、用户名与密码成对出现、内联密钥与环境变量二选一、
  空白内联密钥被拒绝、内联密钥要求 `0600` 权限、`config show` 脱敏、明文 SMTP
  凭据只允许回环、事件列表不能为空或重复、渠道名唯一、邮件地址与 URL 校验。
- 全量：`cargo test -p willdeep --bin willdeep` 与
  `cargo clippy --workspace --all-targets -- -D warnings` 通过。
- TUI / Web 修复：`cargo test -p willdeep --bin willdeep tui::narration::tests`、
  `cargo test -p willdeep --bin willdeep web::tests`；Web 前端 `yarn lint`、
  `yarn build`、`yarn test` 通过。

## 兼容边界

- `[[notifications.channels]]` 只有 CLI 消费；桌面端保存通知设置时整段替换
  `[notifications]`，替换范围在第一个 `[[…]]` 表头前结束，因此渠道表不会被删掉。
- 投递仍是事后旁路：进程退出前的 `flush` 最多等 6 秒，TUI 退出不等待；超时或失败
  只会出现在 stderr / notice 里，不影响轮次结果。
- Resend 的 `Idempotency-Key` 按
  `willdeep-{session_id}-{event}-{occurred_at}` 生成；SMTP 没有去重机制，重投就是
  多发一封。
