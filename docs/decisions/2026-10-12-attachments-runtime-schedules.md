# 附件管理与 Runtime 定时任务规划

日期：2026-10-12。候选版本：0.98.0-rc1。用户已授权全部实现，一起发版并本地安装。功能已实现，预算、超时、Web 附件联动与真实 TUI 协议输出已经验收，发布状态以 GitHub Release 和本地版本读回为准。

验收证据：[Runtime 实际运行报告](../verification/0.98.0-rc1/runtime-management.md)、[TUI 协议输出记录](../verification/0.98.0-rc1/tui-management.json)。图片在受控 PTY 中验证原生协议与半块降级，未操作物理终端窗口。Web 待发队列属于本页面，刷新页面不会持久恢复此本地队列；Runtime 定时任务与运行历史持久保存。

## 现状与问题

- TUI 附件保存在输入草稿或 `QueuedPrompt.attachments` 中，当前附件栏高度固定，多条附件缺少完整管理入口。聊天媒体预览已有终端原生图片协议和 Unicode 半块降级能力，可复用。
- Web 已有附件横向列表、图片小缩略图和删除按钮，但缺少完整列表、大图预览、文本内容查看及待发附件的统一管理。
- 定时触发已经由常驻 Runtime daemon 执行，每 30 秒检查一次 `schedules.json`；关闭 TUI 或 Web 不影响计时。
- 当前调度受 `willdeep-scheduler` 插件是否启用控制。工具主要提供创建、列出和完成删除；任务仅保存最近触发时间及最近会话 ID。
- 当前会记录 fired/skipped/failed 事件，并跳过上次尚未结束的任务，但事件与任务没有组成可分页查询的完整运行历史；完成任务直接删除配置，也不利于回溯。

## 阶段一：附件列表与预览

### 用户流程

1. 输入区持续显示“附件 N 个”，列出少量摘要，超出空间时明确显示还有多少条；提供可发现的“管理附件”入口。
2. TUI 用 `/attachments` 打开独立面板；Web 点击附件计数打开侧栏。列表包含名称、类型、大小、图片尺寸或文本行数，支持选择、移除、清空和调整顺序。
3. 图片可预览、缩放到窗口和恢复适配；TUI 复用原生图片协议，不支持时降级为半块预览，SSH/tmux 下仍能查看名称、尺寸和内容概要。解码不阻塞输入或流式输出。
4. 文本附件支持全文滚动查看及编辑。首期只做已有图片、文本附件，不扩展视频或任意二进制解析。
5. 待发列表中选中消息后，可打开它自己的附件面板；编辑和删除只影响该消息。已经发出的消息只读，可重新引用为新草稿。
6. 打开待发消息的附件面板时继续暂停自动发送。关闭附件面板返回队列列表，最终关闭队列列表才恢复发送。

### 实现边界

- 给草稿附件引入稳定 ID，列表和选中状态按 ID 绑定，不能按名称或数组下标误删同名附件。顺序决定发送顺序。
- UI 元信息与模型附件载荷分开；名称只用于展示，不用作磁盘路径。已有会话附件格式保留兼容。
- 图片预览直接使用已上传/已粘贴的本地载荷，不额外上传给外部服务；限制解码尺寸、内存和缓存数量。
- 保留各端已有上传数量和大小限制（当前 Web 最多 12 个附件）；管理界面显示已用/上限及超限原因，首期不顺带放宽限制。
- Web 文案全部走 i18n，预览支持键盘、关闭按钮与焦点恢复。TUI 的键位先检查冲突，帮助和面板提示同步更新。

### 验收

- 1、5、达到现有上限的附件在窄窗口都可逐条访问，超限请求明确拒绝；重名、删除首尾、调整顺序不误操作。
- 编辑、取消、预览、发送失败和管理期间轮次结束都不丢草稿、不混附件。
- 图片在支持原生协议及降级终端分别实测；损坏/超限图片给出可操作提示。
- Web 测试列表、删除、大图预览、文本编辑和键盘操作，窄屏不遮住发送入口。

## 阶段二：Runtime 原生定时任务与 Web 管理

### 所有权与兼容

- Runtime 是唯一配置写入方、调度方和运行历史写入方。CLI、TUI、Web 与插件调用同一组 Runtime 接口，客户端不设自己的计时器。
- 插件保留自然语言创建任务的能力，改为调用 Runtime API；停用插件仅关闭该入口，独立任务的暂停与恢复由 Runtime 管理。
- 迁移旧 `schedules.json` 时保留任务 ID、配置、最近会话及启用状态。旧插件未启用时导入为暂停并标记迁移原因，不能突然启动无人值守任务；提供迁移摘要和显式恢复入口。
- 旧数据没有完整历史，不编造“以前成功了多少次”；最近会话可显示为旧版本导入记录，早期未知状态明确标记。

### 任务与运行记录分开

| 对象 | 主要字段 |
|---|---|
| 任务定义 | ID、名称、提示词、工作区、模型/路由、审批档位、时区、计划、状态、下一次运行、创建/更新时间、配置修订号 |
| 运行记录 | Run ID、Task ID、计划时刻、触发来源、配置快照、排队/开始/结束时间、会话/轮次 ID、状态、失败原因、验证结论、用量 |

- 任务状态：启用、暂停、目标达成、归档。目标达成停止未来触发但保留配置和历史；归档代替直接删除。永久删除作为单独动作。
- 运行状态至少区分排队、执行中、等待审批、等待回答、成功、部分完成、失败、取消、跳过、未知。执行结束与目标达成分开，不能把“进程结束”当作目标完成。
- 每次运行保存当时的提示词、模型和计划快照；以后改任务不能改写过去的记录。敏感字段脱敏，权限遵循已有工作区和 Runtime 访问约束。
- 用量、费用或验证信息未采集时显示“未知/未验证”，不当作零费用或成功。运行开始/结束存 UTC，界面同时说明任务时区。

### Web 管理界面

- 左侧导航增加“定时任务”。任务列表显示状态、工作区、计划/时区、下一次运行、最近结果，可按名称、状态和工作区筛选。
- 任务详情分为“配置”和“运行历史”。配置支持新建、编辑、复制、暂停/恢复、立即运行和归档，并显示未来几次运行时间供校验。
- 历史按时间分页，可筛选失败、跳过或等待人工处理；显示耗时、触发原因、模型、用量、结果概要，点击进入对应会话查看实际输出、工具执行与验证证据。
- 正在运行的条目可停止。失败记录可明确重试，创建新的运行记录并关联原记录，不覆盖原历史。
- 任务编辑只影响未来运行；停止任务计划与停止当前运行是两个明确操作。

### 调度可靠性

- 首期保留每 N 分钟、每天、工作日、每周，加入单次任务和显式 IANA 时区；复杂 cron 暂不纳入。
- 同一任务默认不重叠：上一轮未结束时创建“跳过”记录，写明原因。全局并发上限与 Runtime 资源预算共用。
- 重启或休眠后默认最多补一次，不连续补跑所有错过时刻；逐条记录补跑/跳过原因。任务可选择完全不补跑。
- 用任务 ID、计划时刻与修订号生成稳定触发键，先持久化运行记录再以幂等请求 ID 入队。重启时核对已有会话/轮次，避免重复入队。这里只保证触发/入队去重，不宣称外部副作用严格执行一次。
- 首期沿用 Runtime 文件存储：任务配置原子更新、运行记录按任务及 Run ID 分文件，建立可恢复的分页索引，Runtime 单写入。暂不新增独立数据库。
- 连续失败按任务策略暂停并显示原因；网络或模型流中断不自动重放已开始的运行。普通失败留在历史，审批或需人工处理的情况沿用已有通知机制。
- 无人值守任务不自动提高审批权限；需要用户授权时进入明确的等待状态，Web 可处理审批或回答。任务级最大时长、轮次和 Token 预算沿用 Runtime 预算机制，详情显示配置与实际消耗。
- 归档默认保留历史，提供保留期限和清理预览；不能清掉仍在运行或等待人工处理的记录。

### Runtime API 草案

以已有 Runtime 路由风格为准，接口职责如下，路径在实现阶段最终确认：

- 任务列表、创建、详情、按修订号更新、暂停、恢复、立即运行、归档。
- 按任务查询分页运行历史、运行详情、停止、显式重试。
- 验证计划与时区、预览未来运行时刻、查看旧任务迁移结果。
- Web 后端代理 Runtime 接口，不直接改调度文件。Runtime 协议与客户端 SDK 同步提供相应类型；响应沿用现有版本 header。

### 验收

- 关闭 TUI/Web、重启 daemon、休眠恢复后任务仍可管理，历史能解释是否执行及为何跳过。
- 覆盖时区、夏令时、重复触发、编辑竞态、上轮未结束、审批等待、故障恢复和显式重试；使用可控时钟与隔离存储，不依赖真实分钟等待。
- 迁移保留旧任务及启用意图，插件关闭不会意外触发；旧工具调用兼容。
- Web 新建→暂停→恢复→立即运行→查看历史→打开会话→停止/重试→归档完成端到端验证。

## 建议实施顺序

1. 附件稳定 ID、TUI 列表、图片/文本预览、待发附件管理；同步完善 Web 附件侧栏。
2. Runtime 任务/运行存储与管理 API、兼容迁移、调度去重和恢复测试。
3. Web 定时任务页、配置与历史页；CLI/TUI 共用 Runtime 管理入口。
4. 故障恢复与真实客户端验收，完成全部验收后统一发版并本地安装。每阶段只新增该阶段需要的能力，避免把定时管理、通用工作流和媒体格式扩展一次打包。
