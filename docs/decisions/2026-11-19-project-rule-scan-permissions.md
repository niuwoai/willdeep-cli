# 项目规则递归发现的权限边界

日期：2026-11-19

目标版本：0.153.0-rc6

## 问题

执行 `run_command`、`monitor`、`spawn_agent`、`call_mcp_tool` 和 `mcp__*` 前，Core 会递归发现工作区的 `AGENTS.md`、`CLAUDE.md`。这些工具的路径语义不透明，不能依靠命令文本猜测规则作用域。原实现将所有遍历错误直接返回；工作区中一个无关的私有子目录不可列举，也会使工具在实际执行前失败。

## 决策

仅对递归发现阶段的目录权限错误容错，且必须同时满足：

- 底层错误为 `PermissionDenied`，遍历深度大于零。
- 错误携带工作区内严格子路径，路径不含父目录跳转。
- 目标名称不是 `AGENTS.md`、`CLAUDE.md`。
- `symlink_metadata` 可以确认目标为普通目录，不跟随符号链接。
- 对 `目录/.` 的 metadata 查询也明确返回 `PermissionDenied`，确认不能通过该目录按已知路径访问内容。仅禁止列举、仍允许路径访问的目录继续阻止执行，避免遗漏其中或更深层的可读规则。

满足条件时跳过无法列举的目录，继续处理其他条目，并向标准错误记录结构化 warning，说明发现阶段跳过了目录。未能扫描的子树不视为已加载规则，也不据此修改文件系统权限。

根目录不可读、路径或深度缺失、未知错误形态、其他 I/O 错误，以及不能确认目录类型的错误继续阻止工具执行。规则文件的解析路径、越界检查、打开与正文读取不进入容错分支。已发现目录仍保留在规则作用域集合中；其规则后来变得不可读时，刷新仍然失败，不能通过修改权限隐藏已加载规则。

保留隐藏目录和 `.gitignore`、`.ignore` 所忽略目录中的可读规则发现，不进入 `.git` 内部、不跟随目录符号链接。发现或修改规则后的首次工具调用仍先返回规则更新提示，模型看到新规则后才可重发工具请求。

## 验证边界

原生 Rust 测试覆盖全部不透明工具、真实目录权限限制、禁止列举但允许按路径读取的 `0111` 目录、规则文件权限变化、已加载目录权限变化、工作区根目录错误和嵌套规则越界符号链接。错误分类使用确定性的合成错误用例，覆盖普通文件、规则名称、缺失元数据、工作区外路径、根深度和未知错误形态。

Unix 权限夹具设置权限后，先验证实际文件系统操作返回 `PermissionDenied`。能绕过权限位的特权进程明确输出该权限用例的跳过原因；不以成功访问作为容错验证通过的证据。错误分类用例不依赖当前 UID。夹具通过 guard 恢复原权限。

本修复不改变工作区选择、工具执行身份、沙箱或系统服务配置。源码验证不等于已在 q3 安装；远端安装与服务升级单独记录。
