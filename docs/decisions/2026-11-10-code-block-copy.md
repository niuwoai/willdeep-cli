# TUI 代码块整块复制

> 日期：2026-11-10 | 状态：已实现，待发布 | 版本：0.147.0-rc24

## 背景

用户希望点击或选中代码块时，能一键复制整块代码并得到反馈；如果终端是 MuseTerm，希望有更接近 Web 的浮动复制按钮。TUI 运行在任意终端里，不能假设对方支持私有图形协议；同时 MuseTerm 已经能通过环境标记被识别。

## 决策

采用两层实现，互不依赖：

1. **跨终端基线：双击整块复制。** 在 Markdown 渲染时记录每个围栏代码块的源正文和折行后的屏幕行范围；两次左键按下落在同一块内、间隔不超过 450ms，松手即复制围栏之间的原始行，并把整块作为可继续操作的选区。复制内容不取屏幕折行文本，避免续行被插入换行、缩进被破坏。
2. **MuseTerm 增强：浮动复制徽标。** 仅在 `gallery::hosted()` 为真（`MUSETERM_AGENT_CONTEXT` / `QTERM_AGENT_CONTEXT`）时，单击代码块会在块可见部分右上角画一个 `⧉ 复制` 标签；点击复制，两秒内显示 `✓ 已复制` 或 `✗ 失败`。徽标是 TUI 自己画的单元格覆盖层，不新增终端协议，也不改 MuseTerm。

剪贴板路由：

- 本机优先写系统剪贴板（arboard）；MuseTerm 和 SSH 会话同时/优先发 OSC 52，让终端把正文写进用户本机剪贴板。
- tmux 内自动套 DCS passthrough；GNU screen 等不支持的环境直接回落或明确报错。
- OSC 52 没有回执。只有本机剪贴板确实写成功时才说「已复制」；只发出 OSC 52 时说「已发送」，不把「已发送」冒充「已验证」。
- SSH 上不写远端 arboard；远端通常没有可用显示，写了也对用户没有意义。

## 结果与边界

- 双击在任何能上报鼠标按键的终端可用；`Ctrl+C`、`Y`、`Q` 和 `Esc` 沿用现有选区语义。
- 徽标只在识别到 MuseTerm 时出现，其他终端完全不画，符合「不是 MuseTerm 就无视」的要求。
- SSH 不会自动转发 `MUSETERM_AGENT_CONTEXT`，所以远端进程通常没有徽标；双击和 OSC 52 兜底仍然可用。
- 徽标覆盖代码块右上角的少量单元格，是浮层的固有代价；滚动、点击别处或 `Esc` 会收起。
- 不做 hover 触发：鼠标捕获已经开启 `?1003h`（上报所有移动），再为悬停增加状态只会放大低带宽链路上的上行流量。

## 备选方案

- **MuseTerm 原生浮层 + 私有 OSC 通道**：UI 上限最高，但需要跨仓库改 MuseTerm、维护新协议和安全边界，发布节奏耦合，且 SSH 下环境标记同样不自动生效。先以零终极端改动的方案落地；如果后续把像素级 hover 浮层当作明确的 MU 差异化能力，再单独立项。
- **只做双击，不做徽标**：可用但发现性差；MuseTerm 里补一个可见入口的成本很低，且与 Web 的每块复制按钮语义一致。
- **徽标对所有终端显示**：会破坏非 MuseTerm 终端的界面预期，也违背用户「不是 MuseTerm 就完全无视」的要求。
