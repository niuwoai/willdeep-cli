# TUI /btw 临时问答与输入区待发消息

日期：2026-11-17。

状态：设计提案，待用户确认后实现。核查基线为当前 worktree 的 `0.149.0-rc10`，包含尚未提交的用户消息排版改动。本文件和交互草图不代表功能已经实现、测试、安装或发布；本轮只增加设计材料，不提升代码版本。正式实现属于功能新增，届时按实际最新版本提升 MINOR 并重置为 `rc1`，同步版本、CHANGELOG、产品概览与架构/API 文档。

交互草图：[可操作 HTML](../assets/tui-btw-queue/interaction-preview.html)。草图只操作页面内存，主任务计时与回答均为模拟，不连接 Runtime 或 Provider；它演示面板、焦点与编辑方式，不模拟服务端竞态、用量和取消协议。

## 目标与范围

本项目属于既有产品迭代：Ratatui/crossterm TUI、持久 Runtime 队列、弹层路由、完整/简洁布局以及中英日界面均已存在。本次沿用这些体系。

两个入口解决不同问题：

- `/btw <问题>`：在主任务继续运行时，基于提问时的对话快照回答临时问题。问答显示在可关闭的专用面板中，不成为主任务的下一轮指令。
- 输入框上方的待发消息：让用户随时看见已经排队的下一步指令；可以原位编辑，并清楚知道何时会发送。

首版交付 TUI 的两项交互与必要的 Runtime/Core 能力。Web、手机与 Swift 不在首版增加入口；新增 Runtime 契约需要兼容旧客户端，并为以后接入保留结构化能力，不复制各端执行逻辑。不改 Xedit 的共享配置、技能或工种契约。

## 参考图的可见信息

用户提供的图 1 显示：主任务活动状态仍可见，`/btw` 问题和 `Answering…` 位于单独区域，提示 `Esc to close`。图 2 显示：待发消息以低对比背景行展示，附立即发送快捷键提示；主输入框为空时提示按 ↑ 编辑队列。

已对照 [Claude Code 官方交互说明](https://code.claude.com/docs/en/interactive-mode.md#side-questions-with-btw) 核实：`/btw` 无工具、可在主任务运行时独立回答、不包含尚在生成的主回复、问答不进主历史；面板一次回答，后续 `/btw` 可带上最近 20 组旁问，裸 `/btw` 可重开最近问答。原文包括 “The question and answer never enter the conversation history” 与 “No tool access”。文档明确回答显示后的 Escape 关闭，没有明确证明生成中 Escape 会停止上游计算。willdeep 的“生成中 Esc 关闭并请求取消”是本提案自己的决策；本地断开也不能保证上游立即停止计费。

同页的[队列说明](https://code.claude.com/docs/en/interactive-mode.md#queue-messages-while-claude-works) 确认灰显、Up 取回以及立即发送快捷键。但 Claude Code 可将普通文字在工具调用后送入同一轮，Up 还可能将多条取回合并为一个输入；willdeep 的持久队列仍按自己的串行调度与原位编辑契约执行。只借鉴入口和可见性，不把不同的队列语义混成一套。

## 已有能力与必须保持的边界

- Runtime 是已提交队列的权威来源；客户端草稿归客户端。忙时普通输入入队不代表当前模型已经读取。见[Runtime 产品边界](../product/runtime-sessions.md#持久队列与人工等待)。
- `turn.queue.update` 已提供编辑、删除和 `send_now`。编辑按消息 ID 和旧文本快照校验，保留附件、顺序及宿主上下文；调度认领与队列修改互斥。见[控制 API](../RUNTIME_CONTROL_API.md)。
- Runtime 的 `send_now` 会将目标提前；**2026-11-24（#208）** 起默认**不**停止活动轮：执行中可对纯文本项 steer，否则等当前轮结束。等待人工交互时还须保持原请求及依赖检查；不能承诺无条件立刻启动。它不能用作 `/btw` 的实现路径。
- 默认 Runtime 队列在管理期间仍可调度；显式 `/local` 才有进程内插话及面板暂停发送的特殊语义。两者必须分别处理。
- 当前输出生成时需在 800 毫秒内连按两次 Esc 才中断；单次 Esc 先处理弹层。空输入框的 ↑ 已有历史输入入口，新队列编辑入口需要明确优先级。Ctrl/Cmd+Enter 当前显式入队为 `held`，无论忙闲都须释放后才参与调度，不改成 Claude Code 的立即发送键。见[TUI 产品模块](../product/cli-tui.md)及下方源码索引。
- 已发用户消息沿用右侧背景块；待发条目属于状态层，不冒充已发送消息。保留[当前消息排版约定](2026-11-16-tui-user-message-blocks.md)。

## 布局选择

| 方向 | 优点 | 代价 | 建议 |
|---|---|---|---|
| 输入区附近的底部面板 | 保留主输出及活动状态；贴近发起位置；窄屏可用 | 需要共享高度预算与独立滚动 | 首选 |
| 居中弹窗 | 容易复用现有模态框 | 主任务输出容易被遮挡 | 作为极小窗口降级 |
| 常驻右侧分栏 | 宽终端可同时阅读两边 | 挤占正文；与现有侧栏竞争；窄屏需另做布局 | 首版不选 |

推荐采用底部面板，延续现有终端字体、颜色和完整/简洁模式。用户可以在确认设计时调整方向；实现前以本文件回写确认结果。

### 正常运行与待发消息

```text
助手正文、工具摘要与进展……

主任务运行状态……

待发送 · 2
  1  完成后再检查窄屏下的排版。           附件 1
  2  把新的快捷键写进使用指南。
  ↑ 编辑下一条 · Ctrl+Q 管理全部
──────────────────────────────────────────────
❯ 输入下一条消息……
──────────────────────────────────────────────
```

待发区域固定在输入区上方，不随着聊天记录滚走。主任务活动状态仍单独可见；队列行与活动区的最终上下次序以真实 PTY 验收为准，不能因队列出现把活动状态或输入框挤出屏幕。

默认显示按 Runtime 返回顺序排列的前 2 条，每条最多 2 个终端显示行；其余显示“另有 N 条”，可进入完整列表。主动暂缓的 `held` 项明确标“暂缓”，不能说它会在本轮结束后自动发出；优先项/独立处理项沿用服务端的真实标记。此限制只影响预览，不裁剪消息或附件。长路径、中文、换行和宽字符按现有布局宽度处理。

每条至少有正文预览、附件数量和必要状态；可编辑、提交中、提交失败、已开始必须可区分。提交中不能标成已持久保存，取消/失败不能标成已发送。跨端新消息由 Runtime 刷新进入同一投影；重复文本按不同消息 ID 分别显示。

已启动时队列条退出待发区，聊天区只出现一次正式用户消息。此前的乐观回显必须按提交/消息身份认领或替换，不能以文本相等去重；首版可以选择迁移现有回显位置，但必须回归消息时间、附件与等待/压缩动画。

队列为空时不占位。输入框已有文字或附件草稿时，不能用队列提示盖住草稿或下一步操作。

### /btw 临时问答

```text
主对话仍在更新……
主任务运行状态……
──────────────────────────────────────────────
临时问答                            Esc 关闭

/btw 队列里的消息会打断现在的任务吗？

正在回答…
随后在此流式显示答案，长答案可滚动。

基于提问时的上下文 · 不进入主对话
──────────────────────────────────────────────
```

- `/btw <问题>` 直接打开面板并开始回答。仅精确匹配命令和参数边界，不匹配 `/btwfoo`；消息正文中的 `/btw` 不被再次解析成命令。
- `/btw` 不带正文时，若当前客户端/Session 有已完成的临时问答，重新打开最近一组；没有时打开独立的问题输入区，Enter 提交，空问题不发请求。主任务运行、压缩、等待审批以及空闲时都能打开，权限和 Runtime 能力不足时说明原因。
- 首版每个面板回答一个问题；继续问时重新输入 `/btw <新问题>`，将当前主对话快照与最近最多 20 组已完成旁问作为资料。旁问在内存中按客户端、Session 和工作区隔离，受总 token/内存上限约束，显示已保留范围，提供明确的“清除临时问答”操作。不自动开完整子会话；失败时可明确重试，重试使用新的请求身份并重新记录上下文时间。未完成或已取消的回答标注状态，不作为已完成答案自动重放。
- 主输入框和临时问题输入使用不同状态。通过命令面板发起时完整保留主草稿、附件和光标；通过主输入框输入 `/btw ...` 发起时，只消费这条命令文字，主草稿附件保留，不偷偷作为临时问答附件上传。面板内提示首版只支持文字。
- 回答中显示进度；完成后保留答案直到用户关闭。主任务完成、失败或进入人工等待都不能自动关掉面板。
- 主任务的新审批/提问仍有可见提示。用户主动返回原请求后，既有审批/回答流程接管；临时问题不能变成审批答案。
- 面板内允许滚动、选择和复制，选择坐标独立于主 transcript；不把面板内容插入聊天记录、搜索、会话标题或下一句预测。

## Esc 与焦点契约

| 所在位置 | 一次 Esc | 对主任务的影响 |
|---|---|---|
| `/btw` 的命令候选或面板内子弹层 | 关闭最上层局部 UI | 无 |
| `/btw` 正在回答 | 关闭面板，同时取消该临时请求 | 无 |
| `/btw` 已完成或失败 | 关闭面板 | 无 |
| 队列编辑器 | 取消本次未保存编辑，回到原入口 | 无 |
| 完整队列列表 | 沿用现有关闭规则 | Runtime 调度继续；本地模式沿用现有暂停规则 |
| 普通主界面 | 沿用现有双 Esc 中断规则 | 仅此路径可中断主轮次 |

实现必须先路由当前模态，再判断主任务中断。一旦某个局部 UI 消费 Esc，该事件立即返回，并清除此前武装的主任务双 Esc 计时；关闭按键及其连发不能成为全局中断序列的一部分。需要复用现有双 Esc 窗口并用真实终端键序列验证，避免依赖所有终端都会上报按键释放。

主任务停止和临时问答取消使用不同资源 ID 与取消句柄。不能通过 `turn.cancel`、现有全局 Agent cancel 或 `send_now` 去关闭 `/btw`。关闭后晚到的 token、完成、失败均按请求 ID 和面板世代丢弃；新开的面板不接收旧请求的事件。

关闭或取消编辑后恢复原输入焦点及光标，草稿不变。Ctrl+C 等既有全局退出操作保持明确的既有语义，不借本次迭代重定义。

## 队列编辑与立即发送

### ↑ 的优先级

1. 先处理当前模态、命令候选和多行输入导航。
2. 主输入区获得焦点、没有正文及附件草稿、没有候选、存在可编辑待发项时，↑ 编辑下一条实际将执行的消息。
3. 没有可编辑队列项时，沿用现有历史输入入口。

有正文时 ↑ 仍移动光标，不替换文字；有附件草稿时不把别的消息附件混进来。Ctrl+Q 和 `/queue` 始终是完整队列入口，历史输入仍有既有入口可达。

### 原位编辑

使用专用编辑器，而不是先从队列弹出消息再塞回主输入框。编辑器保存 `message_id`、原始文本快照和本次编辑缓冲；正文保存仍使用既有服务端比较校验，附件管理复用现有队列附件能力。

Enter 保存，既有多行换行键保持；Esc 放弃。临时问题与队列编辑均须避开输入法组合输入：确认或取消中日文候选不能触发提问、保存或关闭面板。编辑开始不撤销、不重新入队、不改变顺序。Runtime 可以在编辑期间领取原消息：此时保存必须失败，显示“这条消息已经开始处理”，保留编辑缓冲，提供明确的复制或另存为新草稿动作，不能静默新发一次。

远端编辑、删除、认领或控制请求失败同样不能清空用户改写。客户端选中项按 ID 跟随刷新，不按行号误操作下一条。编辑后附件、命令执行类型、宿主上下文和提交时间的既有语义必须保留。

### 立即发送

借鉴参考图的可发现性，不直接照搬 `Ctrl+X Ctrl+S`。当前 Ctrl+S 已用于文本选择，首版继续通过 Ctrl+Q 进入列表，使用已有 S 操作；按运行状态显示真实含义：

- Runtime 正在执行普通轮次：显示“优先发送（不打断当前轮）”。
- Runtime 空闲且条目处于主动暂缓：显示“立即开始”。
- Runtime 等待审批/回答：显示“优先处理”，并说明原请求仍待处理、依赖条件可能阻止启动。
- `/local`：沿用本地插话能力与限制，不能标成等价的 Runtime 行为。

不得让“立即发送”成为关闭 `/btw` 的副作用，也不把队列保存成功说成模型已读取。

## Runtime 与 Core 方案

### 推荐：专用临时问答通道

沿用现有 Provider/Streaming/Usage 基础设施，增加宿主辅助问答请求。请求由 Runtime 管理，不提交为主 Session 的 Turn，也不占用/抢走主会话的串行执行锁。完整子会话适合独立执行任务，不适合轻量、随时关闭、无工具的临时问答；主 Turn 队列则天然会等待当前任务结束。

TUI 通过 Runtime Client 发起/观察/取消；`/local` 共用 Core 的快照构造和辅助问答执行器，但生命周期归当前本地宿主。旧 Runtime 未声明能力时明确不可用，不能偷偷回退到取消主任务或把问题入主队列。

新增协议名称在实现时统一到 protocol crate，建议 capability `session_side_questions`，操作 `session.side_question.start/get/cancel`，事件 `side_question.*`。它们是提案名称，不是现有可调用 API。

最低限度的结构字段：Session ID、临时问题 ID、幂等请求 ID、发起客户端关联、快照身份与时间、状态、实际 Provider/模型、结果/错误及用量。流事件必须携带临时问题 ID，不能伪造主 Turn 或 Task ID。普通主对话事件处理、计划完成门、队列排空、通知与首答统计须排除该通道。

### 上下文是单向快照

主对话可以作为临时问答的输入；临时问答的问与答不自动回写主对话。首版没有“让主任务照此执行”的隐式入口；用户明确复制为普通消息提交后才进入既有队列。

快照由 Runtime/本地宿主从已知安全边界生成，包括有效的现有压缩摘要、最近完整对话、当前用户请求，以及有来源的主任务状态。首版将这些内容投影为有明确角色、边界和时间的上下文资料，不重放原始工具协议或隐藏思考。不要把 TUI 渲染后的文本或动画当模型历史。

- 当前 Core 会话文件虽然原子保存，Runtime 元数据、Core 文件与实时流并非同一个事务。首版一次读取完整 Core 快照，再核验可用边界；单独观测的任务状态注明时间与来源，不声称跨文件原子一致。现有 `sanitize_tool_history` 可处理副本中的配对关系；不能因省略未完成调用就断言工具没有发生副作用。
- 忙时读取一致安全快照，不等待主任务结束；锁只用于短暂取得不可变数据，不跨 Provider await 持有。
- 运行中 tool call 尚无 result 时，不复制孤立的 `tool_use/tool_result`；活动工具只能以有时间与来源的状态说明提供。
- 压缩期间用上一份一致快照，并固定摘要代次、消息边界和观测序号；压缩完成不篡改已经发起的问题。
- 不复制隐藏思考、未完成工具参数、凭据或无授权的其他会话。当前权限撤销必须生效，不能借旧快照扩权。
- 输入超过模型窗口时使用已有摘要与有界历史策略，保留当前问题和必要最近语境，显式标记历史范围；不能静默截断后声称看过全部历史。
- 对“当前进展”只能描述截至快照时已观察到的事实，不能把“正在检查”说成“检查通过”。

### 首版工具边界

首版 `/btw` 无工具：不执行 Shell、不读取新文件、不调用 MCP、不派 Worker、不改文件/配置/计划/队列/审批。问题需要未提供的事实时直说无法从当前上下文确认；例如没有可靠的连接信息就不能猜 MCP 指向生产还是预发。

无工具必须由执行器不提供工具定义、不接入工具执行循环来保证，不能只靠提示词。后续如要支持只读查询，应单独定义宿主允许列表及执行约束；MCP `readOnlyHint` 或工具名字不构成无副作用证明。这是扩展边界，不纳入首版任务。

### 模型、容量与用量

- 默认绑定提问时主会话的实际 Provider、模型与合法推理配置；不擅自改用标题模型、便宜模型或固定 Anthropic 模型。运行期间的模型切换不追改已有临时请求。
- 每个面板最多一个活动请求，Runtime 仍需防止多客户端同时创建无限请求；全局并发/速率限制须纳入辅助请求，主任务优先，不为临时问答取消主请求。
- Provider 只允许单并发或没有余量时，面板显示“等待可用连接”，Esc 可取消；不承诺任何模型都能真正同时生成。
- 首版有命名的输入、输出、壁钟和并发限额，具体值在实现和确定性夹具验收时写入协议/配置说明。超限返回明确状态，不能无限追问或无界自动重试。
- 每次临时问答都进入既有调用/用量账本，标记用途和实际请求身份；关闭后的取消也记录已知消耗，Provider 未上报的用量保持未知，不当 0。现有流式账本在调用返回后才结算 UsageTap；接入前要让已观察用量能够在取消/Drop 时交接，不能丢掉取消前已收到的 usage。停止本地处理不等于上游立即停止计费。
- 账户/会话归属统计可汇总临时用量，主 Turn 与持续目标执行预算不得被伪装成临时请求；若现有预算只支持 Turn，需要补清晰归属后再接入，不能绕开总额度。
- Provider 支持流式时逐步显示正文；只支持非流式时显示回答中，完成后一次展示。推理事件不冒充正文或主任务思考状态。

### 生命周期与存储

临时问题、回答和流缓冲首版不作为聊天历史落盘；关闭面板保留有界内存问答，供同一客户端/Session 的裸 `/btw` 重开，退出客户端、清除临时问答或 Daemon 重启后不能恢复。用量与脱敏审计元数据仍按既有账本持久记录，具体正文留存遵守既有策略，不能承诺没有任何日志。重新打开已有答案不额外发模型请求。

客户端关闭回答中的面板、切换 Session/Workspace 或退出时取消自己持有的临时请求；关闭已完成答案只影响显示，主任务及已持久排队消息照常保留。面板可见性不得加入本地队列的暂停/ready 条件。Runtime 侧用流断开/租约或有界超时兜底回收，不能只靠客户端送达 cancel。Daemon 重启后不自动重放临时请求；显示中断，允许用户显式重试。drain 不接受新请求并按有界策略收尾，不能因无人阅读的临时请求长期阻塞升级。

## 显示与本地化

- 字体与字号继承终端，不新加独立字体设置。普通文本、标题、状态和快捷键沿用现有层级；颜色从现有主题语义读取。
- 待发条目用比已发用户消息更弱的中性背景；正文正常对比度，条数/附件/键位用次要颜色，状态仍有文字，不只靠颜色。
- `/btw` 标题与分隔线使用现有强调色；错误使用既有错误样式。答案复用现有 Markdown 与终端控制字符转义，不共享主聊天行号或选区。
- 面板高度由实际视口和输入区预算决定，通常不超过聊天可用高度的一半；极小视口切为专用覆盖面板，同时保留可见的主任务状态和关闭提示。full、compact 与 F2 展开输入都必须有一致行为。
- 资源覆盖简体中文、英文、日文，默认与 fallback 沿用现有设置，无新增 RTL 范围。所有产品文案进既有本地化资源/语言入口，不散落在新视图中。
- 核心状态包括未提交、排队/等待连接、回答中、完成、失败、取消、能力不支持、无可靠上下文、编辑冲突和提交失败。失败原因脱敏且可操作，不显示内部请求载荷。

## 验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 主任务在流式生成时 `/btw` | 主输出继续推进；临时答案只在面板显示；主历史无临时问答 |
| 主任务工具调用/压缩中 `/btw` | 使用一致安全快照，无孤立工具协议；无死锁、重复压缩或主取消 |
| 回答中按 Esc | 面板关闭；只取消临时请求；晚到 token 不进入主聊天或新面板 |
| Esc 连发、先前已有一次主 Esc | 局部消费清除全局中断武装；关闭动作不误停主任务 |
| 完成/失败后关闭 | 仅关闭面板，恢复焦点与草稿；失败可明确重试 |
| 裸 `/btw` 与空问题 | 有已完成答案则重开且不新发请求；否则仅打开问题输入，空白不提交 |
| 中日文输入法候选确认/取消 | 仅完成输入法操作，不误提交、保存或关闭面板 |
| 主任务在面板打开时结束 | 答案保留可读，主状态更新；不自动发送临时问题 |
| 主任务出现审批或工具问题 | 原请求保持真实待处理；临时输入不作回答/批准 |
| 能力不足、断线、Daemon 重启 | 明确失败/中断，无自动回放或主队列降级 |
| 单并发 Provider | 可取消的等待状态，不取消主调用、不突破并发限制 |
| 无工具约束 | Fake Provider 尝试返回工具调用也不执行；不注册 Shell/MCP/Worker |
| 用量返回/未返回/取消 | 实际值或未知准确落账；请求身份不串入主 Turn 用量 |
| 0/1/多条/重复正文的待发消息 | 条数、顺序、预览与附件正确；相同正文按 ID 独立 |
| 空输入 ↑；有文字/附件 ↑ | 前者编辑下一条，后者保护草稿与导航；无队列回到历史入口 |
| 编辑保存与 Runtime 认领同时发生 | 只发生一个合法结果；过期保存拒绝且保留改写，不重复入队 |
| 跨端编辑/删除及控制请求失败 | 按稳定 ID 定位；显示冲突原因；草稿与原附件不丢 |
| 消息开始执行 | 待发区退出该项；正式用户回显只出现一次，时间和附件归属正确 |
| Runtime /local 的 S 操作 | 文字与真实调度一致，不把中断优先发送说成无中断插话 |
| full/compact、F2、窄屏和中英日 | 输入、活动状态与关闭入口可达；换行、滚动、复制与命中坐标正确 |

核心状态和快照边界用 Rust 原生单元测试；Runtime API 和真实 PTY 验收优先 Ruby，输出 JSON 与 Markdown 报告。使用私有临时 HOME、隔离 Provider 与独立 PTY，不操作真实 daemon、剪贴板或用户生产会话。设计阶段不运行应用构建或真实模型请求。
