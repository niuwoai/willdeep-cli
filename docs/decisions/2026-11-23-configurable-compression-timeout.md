# 压缩等待可配置

日期：2026-11-23。候选版本：0.155.0-rc1（与 hooks 契约、MCP 独立文件一起汇入）。既有项目迭代，未安装、未公开发布。

## 背景

0.154.0-rc11 给压缩加了硬上限：整次 120 秒，单个候选 45 秒（见[会话恢复时的摘要复用与压缩等待](2026-11-23-compaction-resume.md)）。45 秒按托管小压缩器定，慢推理模型做兜底时经常超过；而且 3 段历史乘以 45 秒已经是 135 秒，再加上归并和二次压缩，固定的 120 秒总预算根本盖不住。

压缩失败是失败关闭的：检查点写不下去，整个回合失败，而持久历史不变，下一次仍然从第一段开始。所以等待必须能按实际历史长度调，不能靠把默认值一次性拉长。

## 决策

- 单段候选等待默认改为 60 秒，可用 `[agent] compressor_candidate_timeout_seconds` 调，区间 15–180 秒。
- 整次总预算不再固定 120 秒。不写 `[agent] compressor_timeout_seconds` 时，按这段历史实际切出的块数计算：每块一次候选等待，再加归并和二次压缩各一次。块数要等到切块之后才知道，所以预算在开始摘要时才建。
- 写了总预算就用配置值，但不能短于单段等待，否则第一段都没机会跑完。上限 600 秒，一次卡住的压缩不能把整个回合冻住十几分钟。
- 两个键在配置文件、配置工作台和聊天编辑里都能改。Rust 的 `validate` 与配置服务的 `dependency_error` 用同一套区间和跨字段规则，避免界面存下一份下次启动拒绝加载的文件。
- 没写这两个键的旧配置仍能解析。正在进行的压缩沿用开始时复制的设置，下一个回合或空闲时的 `/compress` 才读新值。

## 验证

原生测试覆盖：不写配置时总预算等于块数加二乘以候选等待、写了就用配置值、区间外和总预算短于单段等待被拒绝、设置从配置复制到压缩快照。Ruby 配置服务测试覆盖两个键的保存回环以及非法值被拒绝且不写入文件。既有的超时测试仍通过注入的短预算，不依赖新的默认值。

rc2 修正两处 CI：格式按 `cargo fmt` 改正；聊天配置的 schema 与快照检查改为匹配 `"candidate"` 字段，不再把键名里的 `candidate` 子串当成泄露。

rc3 再修一处：新增的压缩超时校验让 `crates/willdeep-cli/src/config.rs` 超过 3000 行上限，CI 的行数检查因此失败。测试模块原样拆到 `config/tests.rs`，校验逻辑与超时行为都不变。

## 上限调整（#227）

单段候选等待现在允许设置为 15–600 秒，默认 60 秒。整次总预算可显式设置为最多 3600 秒，且至少覆盖一次候选等待。总预算留空时，仍按实际分块数计算。
