# 终端图片列

日期：2026-11-08，2026-11-09 修订。版本：0.147.0-rc13。

## 背景

TUI 的草稿附件之前只能在自己的附件面板里看。在 MuseTerm 里运行时，粘贴板上的图片属于终端进程，willdeep 自己读不到：走 SSH 时它的进程在远程，即使本机运行，它拿到的也是另一份粘贴板。

## 决定

由 MuseTerm 绘制缩略图并读粘贴板，willdeep 保留附件的所有权。两边用私有序列 OSC 7771 对话，帧以 BEL（0x07）结束：

```text
ESC ] 7771 ; v=1 ; <op> ; <字段，以 ; 分隔> BEL
```

- willdeep 启动时先把标准输入换成一个私有 pty 的从端，转发线程读真实终端、滤掉图片帧，再把其余字节写进 pty 主端；装好之后才写 `hello`。终端没见过 `hello` 不会把图片字节写进来，所以没装过滤的程序收不到这些字节。
- 标准输入必须仍是终端。crossterm 第一次读事件时会 `isatty` 并把这个描述符注册进事件源；注册之后再换成管道，事件源还在看真实终端、读取却去了管道，按键就全丢了（rc12 的故障）。pty 两端都是终端，且必须在第一次读标准输入之前装好，所以安装在 `main` 里、会话选择器之前，而不是事件循环里。
- 过滤拿掉 `drop` 和 `delete`，其余字节原样交给按键解析。crossterm 会把 `ESC ]` 变成 Alt+]，所以必须在它之前拿掉。只有「可能是帧头前缀」的尾巴才扣住（例如单独一个 ESC），50 毫秒内没有后续就当作按键放行；箭头键这类完整序列立即通过。
- 草稿里的图片附件变化时写 `list`（JSON 数组，只有 id、名称和是否可删，不带像素）。空列表让终端收起列。
- 收到 `drop` 后解码 PNG，成功则先加入草稿再回 `ack`（`<nonce>;<id>`），失败回 `reject`。收到 `delete` 后删掉对应草稿附件，再回 `remove` 并重新报列表。

已发送的附件不进列表：列上的删除图标只对草稿有意义。

## 限制

只收 PNG，解码后不超过 8 MB，与草稿附件的 12 个、10 MiB 上限一起截断。一帧超过 120,000 字节就丢弃，5 秒还没收到终止符也放弃：前者不会一直吞掉后面的按键，后者不会让半截帧永远占住输入。

只有在 MuseTerm 里（`MUSETERM_AGENT_CONTEXT` 或 `QTERM_AGENT_CONTEXT` 存在）才安装过滤，其他终端保持原样的标准输入。TUI 结束时把真实终端的模式还原，最后三行提示才按正常换行输出；调起外部编辑器前把真实窗口大小同步给 pty，全屏编辑器不会按过期尺寸排版。
