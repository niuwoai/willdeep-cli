## 1. 要解决的问题与推荐决策

设计时的基线中，专业 Worker 能派工、续做和交回报告，完整 Session 能手动分叉、独立对话和互发消息，但两者之间缺少完整子会话的创建与回流编排。P0 的实施与验收结果见[阶段记录](../verification/0.143.0-rc1-p0.md)。

推荐保留两种独立对象：

- **子会话**：把一项可独立推进的工作交给另一条完整对话。用户能打开、插话、处理审批、继续工作；它运行主 Agent Harness，可独立管理上下文。
- **专业 Worker**：在某条会话内执行边界明确的任务，按职责、工具、模型及预算配置运行；主要交回任务报告。

子会话关系回答“这条完整会话在协作树中归属哪里”，任务提出者/创建者回答“谁发起这项工作”，Agent 定义回答“执行者拥有什么职责和能力”，模型绑定回答“本次使用什么模型与窗口”。这些概念分开建模。子会话可以使用与父会话相同的模型，不要求降档；专业 Worker 的三档路由不直接套到子会话上。

分期：P0 交付 `fresh`、共享工作区只读任务、完整对话入口、可靠回报与停止恢复；P1 增加可写独立 worktree 与安全历史分叉；P2 再做接管、脱离及更复杂协作。P0 字段、操作名与默认值以当前协议源码为准；P1/P2 内容保留为后续建议，实施前仍需协议评审。

## 3. 领域对象：关系、任务与执行分开

### 3.1 完整 Session 不新增终态

子会话仍是普通 Runtime Session，拥有自己的 Session ID、root Agent ID、Core 历史、Turn、Task、模型配置和审批状态。它的一次任务结束后会话可以是 Idle，用户仍能继续对话；不得把 Idle 展示成“整个子会话永久完成”。

专业 Worker 继续使用现有 Agent/Run 与 Worker checkpoint 存储，不注册为普通会话列表项。

### 3.2 新增任务发起关系

建议持久保存 `ChildSessionLink`：

| 字段 | 语义 |
|---|---|
| `link_id` | 关系身份 |
| `parent_session_id` | 树形父会话，由宿主绑定；任务提出者/创建者是独立概念 |
| `child_session_id` | 独立完整会话 |
| `created_from_turn_id` | 发起时的父 Turn，用于归属和审计 |
| `context_mode` | `fresh` 或 `fork` |
| `context_source` | fork 的来源 Session、已完成 Turn、消息边界、压缩代数及快照标识；fresh 为空 |
| `workspace_binding` | 已授权工作区及共享/独立 worktree 身份 |
| `delegation_scope` | 发起时已授权范围、子会话能力上限及配置引用；不含凭据正文 |
| `created_at` | 创建时间 |

**不改变 `started_by` 的既有分叉来源含义。** 新关系通过 `parent_session_id` 表达，历史复制来源通过 `context_source` 表达。fresh 可以有父会话而没有历史来源；手动 fork 可以有历史来源而没有受托任务。旧数据只能认定为已知分叉，不能推断出任务订阅和完成承诺。

**截图澄清：提出者/创建者与树形 parent 独立。** 例如主会话 A 把调查交给 B，B 又发现一项后续工作 C，C 可以被提议为 A 下与 B 同级的任务，不必递归派生成 B 的子会话。提出者、受理创建者与最终树形归属不能仅凭缩进互相推断。P0 仍由有权父会话创建并控制直接子任务，禁止子会话再派生，也暂不实现兄弟任务提案入口；上述同级提案能力属于后续方案，不因本次澄清提前开放。

### 3.3 一次委派对应独立任务记录

建议 `ChildSessionTask` 保存 `assignment_id`、`link_id`、`request_id`、`child_turn_id`、实际 Task/attempt 引用、任务简报、状态与时间、结果引用和通知策略。

- `start_session` 创建关系及第一次任务；`continue_session` 在原有子会话上创建新任务，保留其聊天历史。续做、重试和停止入口均校验发起关系及目标任务身份，模型不能借这些入口控制其他会话。
- 首版每次委派绑定一个明确的 child Turn。运行中的补充消息在安全边界进入该 Turn；等待用户审批/回答不是完成。
- 用户直接在子会话里发起的后续工作不自动加入旧任务，不自动重复向旧父会话回报。需要订阅新的任务时必须有新的明确记录。
- 任务状态建议为 `preparing / queued / running / waiting_approval / waiting_answer / completed / partial / failed / cancelled / interrupted / blocked`；最终映射以现有 Turn/Task 枚举为准，不新建互相竞争的执行状态机。
- 跨文件记录由协调器根据权威 Turn/Task 状态恢复投影；不能只凭助手说“完成”改变状态。

显式重试与普通续做区分：`retry_session_task` 在同一 child Session 创建新的 assignment 和 child Turn，记录 `retry_of_assignment_id`；原 assignment 及其终态结果不可变。请求携带 `expected_result_revision`，只允许重试 failed/partial/interrupted/blocked，目标忙碌或旧结果版本不匹配时拒绝。用户取消后的再次执行走明确续做，不自动重试。单个 Turn 内已有的 Task attempts 仍归同一 assignment；只有 Turn 的当前最终 attempt 才能形成该次结果。

受委派的终态 Turn 不允许绕过协调器直接使用原始 `turn.retry` 改写已交付结果；返回应使用 `session.child.retry` 的明确错误。新的显式重试受理后，原结果保留为历史；尚未消费的旧结果带 `superseded_by` 标记，不能冒充最新进展重复启动父续推，已经交付的旧失败通知不撤回。

## 4. 上下文交接

### 4.1 默认 fresh

fresh 创建空聊天历史，并附加有界任务简报：目标、背景、已知事实、文件引用、约束、交付要求、必要附件及来源任务引用。

- 使用主 Harness 的系统契约、当前全局规则、目标工作区规则、Skills/MCP 与模型能力装配流程。系统提示词按当前配置重建，不复制运行中的 Agent 对象，也不承诺字节相同。
- 父模型生成的简报是委派数据，不是用户新授权；宿主显式标记来源。不得为了满足现有 peer-wake 条件而伪造“真实用户输入”。新建任务由已持久化、已授权的委派入口启动。
- 不复制父会话的 Goal、执行计划、排队请求、预算剩余额、未消费消息、审批对象和后台任务句柄。子会话按自己的任务建立计划。
- 简报和附件超过预算时明确拒绝并说明需要缩减的部分；不得静默截断核心目标。首版不隐式调用模型替用户总结全部父历史。
- 默认沿用父会话已解析的 Provider/model；模型覆盖必须来自可用目录，读取目标模型真实能力和窗口。不得给另一模型继承父模型的窗口数值。

### 4.2 P1 增加显式 fork

fork 表示“继承明确边界以前的对话，再执行新任务”，不表示自动压缩，也不等于复制全部执行状态。

- 子会话接口要求指定已完成的 `through_turn_id`。父会话正在执行时，可以读取已发布的不可变完成边界快照；没有这种快照时返回可重试的边界错误，或由调用方明确改用 fresh。
- 不从尚在变更的 `Session.messages` 截取，也不等待当前父 Turn 完成，否则父模型等工具、工具等父模型会死锁。
- 不直接删除 `fork_through` 的 `ensure_manageable`。现有手动 fork 保持行为，新建独立的快照读取路径，由快照版本、消息边界和压缩代数保证一致。
- 快照必须包含闭合的 tool call/result 集合；未完成调用、在途审批、队列和工具副作用不得随历史复制。无法证明闭合就拒绝该边界。
- 复制历史及匹配该历史的上下文摘要；清空执行 checkpoint、Goal/计划控制状态、通知消费标记和运行游标。摘要不得引用被截掉的消息；预算重算，不继承父会话剩余额。
- 附件使用受控不可变副本或内容引用，并校验目标模型能力、文件授权及生命周期。引用不能指向父会话删除后就失效的临时文件。
- 新任务不能取用新边界之后的父会话插话；若那些约束必要，由父模型显式写进简报。

## 5. 工作区、权限与资源

### 5.1 P0 共享目录只读，P1 写入独立 worktree

P0 的 `workspace_mode=shared_read_only` 允许调查、分析和报告；不能把“父子会话各自串行”误当成跨会话文件锁。

- 只读约束是子会话独立的能力上限，不把父会话所在 Workspace 注册表改为只读。
- 文件写入、Shell、Worktree 创建、MCP 及插件副作用按现有 ReadOnly 硬限制处理；`strict` 只是逐次审批，不等于只读。所有直接与间接执行路径都必须校验能力上限，禁止通过 Worker 绕过。
- P0 不开放子会话继续创建子会话，也不开放子会话中的 Worker 派工；读文件等内置工具仍使用主 Harness。后续开放 Worker 时先接通家族配额与能力上限。
- 父会话可能正在修改目录；读取结果带已观察工作区状态说明，跨文件一致性无法保证时明确标记。需要一致代码基线的任务等待 P1 使用固定 worktree，不宣称共享读取拥有快照隔离。

P1 对需要写代码、构建或命令验证的任务推荐 `workspace_mode=worktree`：复用受控 Git worktree 创建、Workspace 绑定与 Diff 审阅路径。非 Git 项目先返回不支持可写隔离，不静默退回共享写目录。

- 默认从明确提交建立工作树。父目录有未提交修改时，不能假装子工作树已包含它们；需要这些修改时使用显式冻结的基线快照，并记录 commit/patch 标识，无法安全取得则阻塞。
- 子会话根目录固定到该工作树；指令、工具、验证器不得硬编码跳回父目录。授权按原项目范围收窄，不能因注册新 worktree 获得更大权限。
- 原 Worker 文件租约只保护参与租约的写者，不能当作根 Agent/Shell 的全局锁。不承诺靠声明文件清单就能安全并发共享写目录。
- 修改完成后交付 Diff、分支/提交引用、检查结果；不自动合并、提交、推送或删除工作树。集成时重新核对目标工作区，按用户授权执行。

### 5.2 独立审批与实际能力

子会话创建时默认沿用父会话的审批偏好，但额外受委派能力上限及当前 Workspace 策略限制。新的共享只读上限必须持久化，并在构建 Harness、工具执行、续做和重启时重新应用。

父子 Session 使用各自审批句柄；给父会话切档不等于给子会话提权。Workspace 的能力撤销必须在执行前生效，子会话快照不能恢复被撤销的 Skills/MCP。扩大子会话授权只能由用户对该会话明确操作，模型工具和协作消息不能做到。

### 5.3 有界准入与预算

建议首版每个根会话最多 4 个子会话执行槽（包含等待审批/回答）、等待队列最多 16 个，自动派生深度为 1；宿主全局子会话执行槽和队列建议同样以 4/16 为上限，多根会话合计受限。这些是待评审默认值，不是现有配置；已结束任务不占执行或队列容量。

准入在 Runtime 原子执行，同时检查根会话族与宿主子会话容量；不能让多个根会话各自计数后无限创建。新建、续做、重试都走同一入口。preparing 记录预留队列容量，首 Turn 入队后转为 queued；排队时不调用模型、不认领工作树、不占执行槽。出队后占用执行槽，再创建工作树并验证授权，启动准备失败时释放容量。

现有 Worker 并发上限按父 Session 计，不能直接覆盖新的完整会话族。P1 在子会话内开放 Worker 前，必须加入家族范围的子会话/Worker 配额与用量归属，避免每开一条会话就重新获赠整套并发和预算。

用量分别展示本会话、本次委派及整个家族。家族统计以实际 ledger 调用去重，覆盖子会话及其 Worker/辅助调用，不再把已聚合 Worker 用量相加。配置家族预算时，入队、出队和新模型请求均检查；并发在途可能超额，不承诺严格费用封顶。

## 6. 模型工具与 Runtime 操作草案

P0 建议公开的模型工具：

| 工具 | 行为 |
|---|---|
| `start_session` | 提交任务简报、标题、`context=fresh` 与通知策略，返回新 Session、assignment 和首 Turn 身份及实际状态 |
| `continue_session` | 在同一子会话创建新 assignment；首版目标忙碌时明确拒绝，不把续做偷换成插话 |
| `retry_session_task` | 指定原 assignment 与预期结果版本，创建带重试关联的新 assignment/Turn；原结果不变 |
| `get_session_task` | 查询本会话发起的 assignment、执行状态、结果与通知状态 |
| 既有 `send_session_message` | 在同项目完整会话间发送短协调消息；不改变授权、归属或结果状态 |

模型工具由宿主绑定发起 Session/Turn、项目、权限及请求幂等键。模型不能指定任意 `parent_session_id`、配置文件路径或凭据。协议层允许合法客户端提供 `request_id`；模型调用由宿主把稳定 tool_call_id 与父 Turn 映射为幂等键。

Runtime 建议增加 `session.child.start`、`session.child.continue`、`session.child.retry`、`session.child.task.get/list`，其控制 API 与模型工具共用协调器。现有 `session.create`、`session.fork` 不承担隐式任务启动副作用。CLI/TUI/Web 通过同一操作，不能各写一套“创建后再发首消息”的拼接逻辑。

P1 才开放 `context=fork`、worktree 与受限模型覆盖；参数能力按 Runtime capabilities 声明。P0 明确拒绝尚不支持的模式，不静默降级。

停止使用已有 Turn 停止机制，并按 assignment 验证 child_turn_id。父会话不获得通用停止所有同项目会话的权限；需要模型发起停止时新增受本关系约束的适配入口。查询可分页，展示列表上限不参与准入计数。

## 7. 创建、启动与崩溃恢复

建议新增私有 `runtime/session-children.json` 协调账本，带 schema、版本和进程锁；维护关系、任务创建意图与结果通知 outbox。消息历史继续只由 Core SessionStore 持有，协调账本不复制全部聊天。

不能靠连续两次 HTTP 请求获得“原子创建并启动”。推荐可重放的准备流程：

1. 校验参数与授权、原子准入；写入 `(creator_session_id, request_id)`、参数指纹、发起 Turn 的取消代数和预分配身份，状态为 preparing；此时尚未正式受理执行。
2. 按固定身份建立 Core/Runtime Session 与关系投影；不复制父 Session 文件后直接改未审查字段。准备对象不允许自行调度。
3. 与父 Turn 的 stop 路径使用同一控制锁及固定锁顺序，重验取消代数与授权，并持久写入 `accepted_at` 和受理代数。**这次成功写入是唯一受理点**；校验与写入必须处于同一临界区。此前已取消则将记录收敛为 cancelled，不提交 child Turn；已建立的准备会话保留可诊断记录，不删用户数据。
4. 以固定首 Turn request_id 持久入队；把 child_turn_id 写回记录，完成 queued 状态，再通知 TaskManager 调度。accepted 后、入队前崩溃时，恢复沿用已持久受理判定补齐入队；父后来的普通停止不撤销已经受理的独立子任务，子会话的显式停止仍有效。
5. 返回持久事实。响应丢失时用同一键重试，返回相同 Session/assignment/Turn；同键不同参数明确冲突。preparing 且没有 accepted_at 的恢复请求必须重新核验取消代数，不得默认自动受理。

每一步可在 Daemon 启动时补齐，不能把未入队的对象报告成已运行。依靠 prepared record 和固定 ID 协调多文件写入，不声称跨文件 rename 构成数据库事务。相同锁顺序和恢复入口须覆盖并发请求；协议的短期幂等缓存不能替代长期任务记录。

Crash 恢复不盲目重放可能已经产生副作用的模型/工具调用。已排队未开始的任务可以重新调度；在途任务按现有安全恢复边界转为 interrupted，并提供用户可见的继续入口。恢复错误保留记录与诊断，不删除仍有用户数据的会话或工作树。

## 8. 完成回报与父会话续推

### 8.1 结果是宿主事实加可选报告

首版通知策略建议 `notify=on_task_terminal` 或 `none`，默认前者，仅订阅当前 assignment；首版不订阅子会话未来所有轮次。一次委派最后由其 Turn/Task 终态及关联后台工作收尾事实形成结果，不能只监听一次模型响应的结束。

`ChildSessionResult` 至少保存 assignment、child Session/Turn、最终 attempt、状态、完成时间、实际模型、报告引用与完整性、工作区/分支、变更与验证引用。状态和身份来自宿主；模型报告只是待父会话核验的内容。失败、取消、部分完成和中断同样产生结果；没有最终正文时明确为“无报告”，不编造成功摘要。

默认投递有界摘要及完整结果引用。建议摘要上限 2,000 个 Unicode 字符，超出明确标记摘要不完整，完整报告按需分页读取；不把整个子会话历史塞回父上下文。

### 8.2 持久 outbox 与幂等消费

- assignment 观察到终态后，宿主按 assignment 与最终执行结果生成稳定 `notification_id`，先持久结果及 outbox，再发送事件。
- 结果通知不伪装成对方模型主动发送的 PeerMessage，也不消耗其普通人际消息限额。可以复用收件箱展示和安全边界注入机制，但通知类型与来源必须区分。
- 父会话正在执行时，在下一安全边界注入；已进入收尾但尚未完成时，必须有持久兜底，不能依赖临时内存 inbox 成功就删 outbox。
- 父会话 Idle 且允许自动续推时，先持久分配 `wake_batch_id`，绑定父会话、停止代数、通知成员及固定 wake Turn request_id，再入队。每个父会话/停止代数至多一个未开始批次；新通知在同一协调锁下加入该批次，不重新选取首条 notification_id 作为身份。wake 入队后、outbox 确认前崩溃，恢复使用原批次和原 request_id，不重新分组或创建新身份。
- wake 开始执行时冻结该批成员；此后新结果走在途安全边界投递或下一批，不改写已开始批次。历史成员与 Turn/消费回执的对应关系保持可查。批次沿用自动唤醒限流，限流时保持为待处理，不丢结果。
- “事件发布”“客户端已读”“模型收到”“结果被处理”分别记录。以父历史/消费回执的持久事实推进确认；断线重启和请求失败后允许再次注入同一 notification_id，并按 ID 去重。
- 交付保证为至少一次传输、固定身份去重及不重复创建 wake Turn；不承诺任意模型决策或外部副作用 exactly-once。停止、失败、重试后的处理仍须核对已有结果。
- 显式重试按第 3.3 节创建新 assignment/Turn 与独立结果通知；旧结果保留审计及 superseded_by 关联。旧 attempt 的晚到事件只能匹配其原 assignment 与版本，不能覆盖新任务或再生成一份“当前完成”。

### 8.3 停止、归档与等待

| 情形 | 建议行为 |
|---|---|
| 父会话普通 Turn 完成 | 子会话继续；它不是该 Turn 的 Worker，不随父 Turn 收尾取消 |
| 用户主动停止父会话 | 只停止父目标 Turn，持久抑制父自动续推；子会话继续，结果保留为待处理 |
| 用户选择停止整组任务 | 展示目标范围，分别停止关联未结束 child Turn；不能波及无关会话 |
| 子会话等待审批/回答 | 通知用户并显示等待；不冒充任务完成，不让父模型代替用户批准 |
| 父会话归档/删除 | 不自动唤醒；保留子会话及来源审计，不级联删数据，结果允许从子会话查询 |
| Daemon drain/重启 | 新启动服从 drain；未完成创建和 outbox 按固定身份恢复，不提前发布成功 |
| 多个结果同时到达 | 批次合并、逐项稳定身份；父会话只保留一条必要的待执行续推 |

停止抑制通过用户明确继续该父会话的操作解除；宿主生成的唤醒、协作来信和子结果不得自行解除。新的 assignment 与结果唤醒需要独立的宿主来源类型，并显式排除现有 `operator_input` 判定；不能只添加一个未经识别的 `origin_client` 前缀，否则它会被当成真人输入并解除抑制。来源只能由 Runtime 绑定。

停止操作持久推进父会话的停止代数；自动唤醒在准入和实际执行前都检查抑制与代数，已入队的旧 wake 失效后转为待处理结果，不执行模型。准备中的创建请求也要检查发起 Turn 的取消代数；在受理点之前被用户取消则不启动，已经成功受理的独立子任务不因父普通 Turn 结束而取消。归档与停止后没有自动续推，并不等于结果被丢弃。

P0 不提供同步等待子会话的模型工具。若将来提供 await，必须释放执行资源并检测依赖环；父任务占满槽位、子任务排队时不得形成资源死锁。

## 9. 界面与文案

Web/TUI 的会话列表使用新父关系嵌套完整子会话，手动分叉继续显示历史来源。首版只自动派生一层；孤儿来源、搜索过滤和旧客户端均保留可访问条目，不隐藏会话。

- 子会话行：任务标题、当前执行/等待状态、未读结果；打开后就是完整聊天，显示“来自哪个会话”及返回入口。
- 父会话：展示任务卡，可打开子会话、查看结果和实际状态；创建不会抢焦点、清草稿或自动切换聊天。
- Worker：保留 Runtime Agent 区的职责、模型、工具时间线、预算和报告；不挪成普通 Session。
- 主会话中显示的“已结束”必须指向具体委派；child Session 为 Idle 时，文案使用“本次任务已结束”。
- 加载、空任务列表、准备中、排队、等待用户、失败、恢复中、结果待处理、来源不可用、权限不足和旧 Runtime 不支持均有明确状态。
- 所有新增可见文案进入现有本地化资源，沿用仓库支持语言及 fallback；本方案的开发术语与验收描述不直接当作产品文案。

Android、Xedit 首阶段允许按普通会话打开历史；新命令仅通过 capabilities 显式开放，不能借通用操作白名单自动扩权。任务简报、配置引用、完整报告和内部路径保存在私有记录中，客户端按既有访问权取得投影；公开分享与外部事件不能因为新增父子关系而自动获得这些字段。跨宿主联邦、共享进程或互用运行状态不属于本轮范围。契约对齐遵守 [双端联动边界](../XEDIT_INTEROP_STATUS.md)。

## 11. 验收与实施门槛

以下为完整分期方案的验收要求，P0/P1 的实际执行结果与未覆盖项分别记录在[P0 阶段验收报告](../verification/0.143.0-rc1-p0.md)与[P1 验收报告](../verification/0.143.0-rc1.md)，不能把表中的后续要求视为已经通过。单测用 Rust 原生框架与 mock Provider；API/端到端优先 Ruby，并输出 JSON、Markdown 报告。Web 交互用现有前端测试及真实浏览器预览；TUI 用 PTY。所有 fixture 使用临时 WILLDEEP_HOME 和合成项目，默认零付费模型调用。

| 场景 | 必须证明 |
|---|---|
| fresh 内容 | 任务简报可见，父聊天/Goal/计划/旧通知不泄入；主 Harness 规则正确装载 |
| 身份边界 | 父 Session 无法伪造；child 有独立 root Agent；Worker 不进入普通会话树 |
| 参数重放 | 响应丢失、并发重复提交返回同一 Session/assignment/Turn；不同参数同键被拒绝 |
| 创建崩溃点 | preparing、Core 保存后、Runtime 保存后、Turn 入队后分别崩溃，重启可收敛，无重复模型执行 |
| 忙碌父会话 | fresh 可立即派生，不等待父 Turn 结束；不破坏现有手动 fork 限制 |
| P0 只读 | 编辑、Shell、MCP、插件副作用和转派 Worker 均不能绕过；父 Workspace 权限不被修改 |
| 容量与队列 | 多根会话并发创建、重试/续做、超过列表页大小均受原子限额；取消与失败释放一次 |
| 回报竞态 | 父执行中/收尾中/Idle、完成与停止竞争、重复终态事件、失败与无报告、旧 attempt 晚到均不丢结果 |
| 通知恢复 | outbox 创建后、wake 入队后、模型成功但历史未保存时分别重启；至少一次投递且不重复创建 wake Turn |
| 停止与归档 | 父被主动停止后不自动拉起；归档/删除不级联删除子会话；用户继续才解除抑制 |
| 使用与续做 | 用户可打开子聊天插话和审批；续做保留 child ID/历史，创建新 assignment；旧任务不重复回报 |
| P1 fork | 完成边界、工具调用闭合、摘要/压缩代数一致、附件存活、无跨越边界泄露 |
| P1 worktree | 明确 commit/未提交基线、隔离路径、权限撤销、并发冲突、Diff 归属与集成后复验 |
| 家族预算 | 子会话/Worker/辅助调用不双计，不因新 Session 重置；在途超额与缺失用量如实显示 |
| 客户端 | Web/TUI 状态与 Runtime 一致、草稿焦点保留、失败可重试、i18n、旧宿主降级可见 |

实施前需要通过的设计检查：

1. 确认 P0 的 fresh+共享只读边界，以及建议的 4/16/1 限额；未确认前把它们保留为提案。
2. 确认新增关系字段和旧 `started_by` 的兼容投影，更新 Runtime DTO、能力声明及协议 fixture。
3. 明确协调账本的锁顺序、prepared 恢复、Turn 权威状态与 outbox 确认条件，先用故障注入证明。
4. P1 开始前先确定工作树基线、快照发布点、模型/附件兼容、家族 Worker 准入；不能仅放开原有 fork 闸门。
