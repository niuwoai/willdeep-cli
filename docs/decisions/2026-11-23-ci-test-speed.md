# CI 退避测试计时与依赖缓存

日期：2026-11-23

合入版本：0.155.0-rc11

## 问题与证据

GitHub Actions 成功运行 [45199061446](https://github.com/niuwoai/willdeep-cli/actions/runs/45199061446) 中，Ubuntu 完整套件耗时 23 分 27 秒，测试编译约 3 分 39 秒，测试执行约 15 分 52 秒；macOS 完整套件耗时 27 分 25 秒，测试编译约 8 分 40 秒，测试执行约 14 分 38 秒。它们是一次运行样本，不是性能承诺。

core 测试组在多个平台均约 421–423 秒，目标续跑阶梯测试进入生产退避路径并等待真实时间。完整套件和 WSL release 构建缺少显式 Rust 依赖缓存；架构测试使用的 cross action 已内置缓存。

## 决策与边界

- core 的 `test-util` 仅声明为 Tokio 开发依赖；目标测试使用 `start_paused = true`，保留原有阶梯和工具调用断言，并用事件时间检查重复错误场景的 60 + 300 秒退避、重复成功场景的 60 秒退避。生产退避时长、可取消等待以及执行逻辑保持原样。
- 本测试配置 `wall_clock: None`，不让标准库墙钟预算与 Tokio 虚拟时钟混用；保留真实文件 I/O，依靠运行时自动推进每次睡眠，不使用一次性大步推进或外层虚拟超时。
- 完整套件与 WSL release 构建使用 `Swatinem/rust-cache@v2`，复用 Cargo 下载及依赖编译产物。共享键区分 OS、CPU 架构和构建用途，action 继续计算工具链、编译环境及依赖指纹；不缓存安装工具和工作区 crate 产物，不保存失败构建。
- 仅 `develop`、`main` 分支允许保存；PR、功能分支派发和 tag 只读取可访问的基线。缓存首次填充在主线成功构建后发生，PR 无基线时继续冷编译。缓存缺失或失败不能成为跳过编译、测试或其他门禁的理由。
- 保留全部平台任务、现有测试命令、Clippy 和打包验证；本轮不引入 nextest，不调整集成测试共享锁，不合并重复的 x86_64 测试任务。
- 不归档整个工作目录或用户配置；缓存仅覆盖构建依赖和所需产物，不包含凭据。

## 验收

本地定向运行修改后的退避测试，确认阶梯断言、虚拟等待时长及真实运行耗时；检查格式、CI YAML 和现有 runner 离线契约，同步 Rust/Web/npm 与产品文档版本。

GitHub 的缓存恢复、保存和托管 CI 总耗时只能由后续真实运行确认。首次填充缓存与后续命中须分开比较，不把本地热构建或测试组耗时当成单条测试精确耗时。

实际本地验证结果记录到 `docs/verification/0.155.0-rc3/ci-test-speed.md`。尚未执行的验证必须明确列出，不以配置已修改冒充提速已实测。
