# 当前请求与完成验证的授权边界

日期：2026-11-18。版本：0.153.0-rc5（develop 已使用 0.153.0-rc2 至 rc4，本次修复由 0.152.0-rc6 顺延）。适用于共享 Core 的 CLI、TUI 和 Runtime 调用。

## 问题

完成门禁曾直接比较任务开始与收尾时的整工作区快照。查询期间其他进程修改文件，也会被解释为本任务缺少测试；门禁随即要求模型继续，查询答案之后可能出现无关项目测试。该路径可以离线复现，但不据此断言某个真实用户会话一定由相同条件触发。

## 授权边界

- 当前明确请求及其必要验证可以自主完成；修复代码后运行相关回归属于该请求。
- 历史记忆、旧任务、旧计划和其他会话的文件修改只能提供背景，不能自动成为本轮待办。
- 超出当前请求必须先询问并得到明确同意。完成门禁、预算提示和历史恢复信息均不授予扩大范围的权限。
- 无关旧待办应隔离，允许当前查询正常结束；不为每个历史待办额外打扰用户。
- 不按自然语言关键词推断只读任务或续跑意图。

## 实现与保守边界

Core 在当前运行中按工具执行前后快照观察变化。内置只读查询（无生命周期 Hook）不建立写入义务；工具之间、模型响应期间出现的整库变化，不自动归属当前请求。成功文件写入继续走严格验证；shell、MCP、委派或 Hook 执行窗口中出现变化时无法证明写者，保留 `Unverified` 并停止自动续跑，不直接要求跑测试。`monitor` 与显式后台命令、自动后台化命令、workflow 和 session 启动一样，返回后仍可能改动工作区，一律保留归属不确定性。该暂停写入检查点的 `completion_scope_uncertain`；后台结果唤醒的宿主续轮沿用同一暂停，不因续轮本身变成严格门禁，也不把旧计划重新装成当前计划。显式恢复沿用原基线并启用严格门禁。

这不是进程级文件审计：无法区分恰好发生在 opaque 工具窗口内的并发写入，也不能证明写后还原、仓库外或远端副作用。对这些不确定性保留原审批与未知效果保护，不把工具成功或屏幕差异当作已通过工程验证。普通查询不生成“验证通过”证据。

普通新输入不把旧计划装入当前活动计划；旧计划在上下文中标记为历史，持久化时保留，等待用户明确续跑。

## 保留的保护

当前任务实际写入、显式验证命令、完成契约、活动 Goal 和显式同任务恢复仍受原验证保护。未知副作用不能冒充成功，也不能自动重放。普通查询完成不等于工程验证通过，不会把旧任务标为已完成。

## 验收

使用私有临时工作区和合成 Provider，复现查询期间的外部变化；分别覆盖纯问答、文件查询、shell 查询，以及本任务文件和 shell 写入。保留已有新输入隔离、显式检查、完成契约及活动 Goal 回归。实际通过范围与限制记录在版本验收文档中。
