# 会话恢复时的摘要复用与压缩等待

日期：2026-11-23。候选版本：0.154.0-rc8。既有项目迭代，未安装、未公开发布。

## 目标与根因

用户希望重新进入刚压缩过的会话后，第一条消息可以复用摘要；同时避免一次压缩等待十分钟。另修复以绝对路径开头的输入被当成未知命令、无法发送的问题。

自动压缩只改变模型请求投影，持久历史保留完整消息。已有 `ContextSummary` 保存压缩前缀及其指纹，调用方也会传回摘要；因此不能靠“重启后暂时不压缩”掩盖失效原因。

1. 每次运行重新构造 `ProjectRules`，初始仅加载工作区根目录。上一轮工具发现过的子目录规则不在首轮系统提示中，导致系统指纹不同，已有摘要失效。
2. 新摘要原先只在成功的 AgentOutcome 收尾保存。压缩已完成、后续主模型失败或被取消时，已完成的压缩工作可能没有落盘。
3. 压缩候选沿用普通 Provider 默认的 600 秒请求期限，分块和候选各自串行等待，整次压缩没有独立总期限。
4. TUI 多处仅凭 `/` 前缀分类输入，因此未知输入不仅会被本地拦截，也跳过回显、附件绑定或普通队列行为。

以上是代码确认的可复现机制，不能据此确定用户截图中的某一次请求具体慢在上游哪个阶段。测试只使用隔离工作区和本机假 Provider，不读取真实会话或凭据。

## 决策

### 规则与摘要恢复

- 根据持久历史中 assistant 的工具调用重建此前发现的规则作用域，不重执行工具，不采用历史文本中的指令。
- 明确文件路径沿用现有工作区边界检查；shell/MCP 等不透明工具重新扫描规则文件，同次恢复只做一次全工作区扫描。
- 重新读取当前规则文件。未改动的作用域产生一致指纹；规则新增、修改、删除或真实消息前缀改写仍可使摘要失效。
- 成功生成的摘要在主模型请求前与对应消息检查点一并持久化。后续检查点保留这一摘要，不依赖主模型成功收尾。
- 展示用 System 行恢复或删除可能改变消息索引，摘要边界必须按相同非展示历史映射，仍验证前缀指纹。无法可靠映射时失效，不能错误复用。检查点、Runtime 首轮及后台续轮、子任务成功收尾共用消息与摘要合并入口，防止成功结果再次覆盖已映射的边界。

### 压缩时间预算

- 每次自动请求投影或手动压缩共用 120 秒阶段预算，覆盖所有分块、摘要归并和二次压缩。
- 每候选最多等待 45 秒，并受阶段剩余时间约束。同次压缩中已超时的候选不在后续分块重复等待。
- 上层运行预算仍有效，实际允许时间取各预算限制。普通主模型请求的超时与推理设置不变。
- 超时、候选耗尽或归并未收敛都明确报错。原始历史、已有有效摘要和已收到的用量继续保留；不截断历史冒充压缩成功。
- 该预算使等待有界，不承诺任意上游、任意长度历史都能在 120 秒内成功压缩。需要极长压缩的后续配置需求另行评估。

### 命令与提示词

- 按首个词精确匹配命令目录、已有别名及保留的插件命名空间，已知命令参数由原处理器校验。
- 未命中的 `/...` 输入作为普通提示词，统一回显、附件绑定、审批等待和运行中排队。
- 显式命令候选菜单的补全行为保持现有交互。

### 重试诊断

- Provider 仍允许首次请求加最多五次重试；所有尝试、响应处理和退避共用一个请求期限。
- 默认退避为 2/4/8/16/32 秒，并遵守有效 Retry-After。这里的 2 秒是下一次请求前的退避，不是请求时限。
- 因剩余时间不足停止时，诊断显示尝试次数、已耗时、所需退避及剩余时间，保留原始错误链。

## 验证与交付

原生 Rust 测试覆盖规则恢复、摘要在出错/取消后的持久化、候选及阶段时限、计费和未知斜杠输入。Ruby PTY 夹具驱动真实 TUI 与隔离 Runtime，核对路径和未知命令进入本机假模型、已知命令参数错误不出网，输出 JSON 与 Markdown 报告。
