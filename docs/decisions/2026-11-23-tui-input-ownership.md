# TUI 滚动、原生选择与人工交互的输入归属

日期：2026-11-23。候选版本：`0.154.0-rc8`。这是既有 Rust TUI 的交互修复，沿用 Ratatui/crossterm、现有主题、full/compact 布局和中英日 `Language::text` 入口。用户已要求把回看时的布局问题与 `ask_user` 偶发点击无反馈一起改良。

## 已确认的缺口与诊断边界

- `Ctrl+S` 原生选择关闭鼠标捕获后，异步到达的提问或审批仍可显示，但此前没有在显示前恢复捕获。人工弹层存在时，原生选择快捷键也先于弹层按键分发。
- 原生选择只暂停正文自动跟随，后台状态仍会触发重绘，可能干扰终端原生选区。
- 提问的底部提示原先按整行左右半边推断发送/跳过，动作没有与真实文字位置绑定；提示换行后不登记点击区域。
- 提问正文没有鼠标滚动视口，审批框外点击可能操作底层界面；聊天选区也会吞掉位于侧栏上的滚轮。连续滚轮跨区时原先可合并到最后一个区域。
- 用户截图中的旧侧栏重复仍需区分应用内部视口与宿主终端的整屏历史。上述代码路径可确认输入状态缺口，但不能据此断定宿主为何保存了旧画面。

## 产品与实现约束

1. 保留一屏工作台：聊天、侧栏和弹窗分别拥有各自滚动区域；输入区或空白处滚轮不应意外滚动聊天。仅在同一区域内合并连续滚轮，跨区域的事件按原顺序继续分发。
2. 内建拖选作为日常复制入口，继续保留原文、阅读锚点和后台新内容提示。回看时后台任务继续运行、事件继续保存，不为固定画面暂停 Runtime。
3. 原生选择进入后绘制一次选择状态，随后冻结常规画面输出；后台事件继续消费。退出选择、窗口缩放或交互弹层出现时恢复鼠标捕获并完整重绘。窗口缩放会结束终端原生选择；应用内部原文选区仍沿用既有重排保持机制。
4. 在主循环绘制前统一同步终端输入归属，覆盖本地消息、Runtime 快照、请求恢复和队列晋升等弹层来源。实际鼠标捕获状态由终端层记录，仅在状态转换时输出控制序列。外部编辑器返回后与其已恢复的终端模式保持一致。原生选择期间收到粘贴时先退出选择并聚焦输入，恢复可见草稿预览，避免积累看不见的输入。滚轮合并先处理较早暂存事件，不越过按键读取较新的输入流。
5. `Ctrl+X` 继续作为当前轮次的独立中断入口。提问/审批随后优先处理键盘，不被聊天或草稿选区的复制、引用和取消快捷键截走；交互弹层打开时不能进入原生选择。
6. 提问与审批消费全部鼠标事件，框外点击不提交、不拒绝，也不操作底层。提问正文使用独立滚动偏移，绘制与命中共用布局；选择、答案编辑与窗口变化按当前目标恢复可见区域。
7. 提问显示明确的发送、跳过按钮，从实际绘制的矩形生成点击动作；提示文案不再充当按半屏猜测的按钮。保留单选点选即发送、多选点选勾选，以及键盘 Enter/Esc 语义。其他答案支持可见文字点击定位。
8. 新按钮与提示使用既有中英日资源；不添加 UI 框架，不改变 Runtime 协议、审批授权、会话持久格式或任务调度。

## 验收范围

- 原生测试：捕获开启/关闭控制序列、原生选择冻结/恢复、异步人工弹层、草稿保留、滚轮跨区顺序、选区期间侧栏滚动、弹窗真实绘制与点击坐标、多语言窄屏、长菜单滚动、答案点击编辑、审批不穿透。
- 真实终端：遵循 `run` 技能，启动实际候选二进制，使用 Ruby 驱动独立 PTY、私有 HOME/工作区、回环合成 Provider；保留 JSON 与 Markdown 报告及终端帧。不调用真实模型、真实凭据，不操作现有 daemon 或真实剪贴板。
- 宿主终端自行保存的备用屏历史不能由应用按列改写。隔离 PTY 能验证应用输入与输出序列，不代表所有终端的原生回滚行为已验证；最终报告须明确这一边界。
