# 首轮已保存回答的免费格式回放规则

本次由用户明确要求修正格式识别并免费回放。原始账本、回答、verifier、manifest、正式报告、原生制品及其源码均只读；新结果写独立目录。不创建 Host、Account 或 Provider，不进行模型请求、付费评测、晋升或发布。

## report-json-v5 解析规则

- 从完整报告中提取唯一完整的三字段 JSON 答案，保留严格字段、类型、重复键与字符串转义检查。提取不接收题目 oracle，不按正确答案选片段。
- 识别闭合 Markdown 行内代码及反引号/波浪线围栏。普通代码块、代码控制结构、对象字面量以及 JavaScript `${…}` 模板插值中的花括号不再充当 JSON；JSON 字符串内的反引号和花括号保持原值。模板插值中的完整答案仍参与歧义检查。
- 只有闭合行内代码中、结构明确的 `{"has_defect":...,"line":...,...}` 省略引用，以及三字段结构中 reason 恰为 `...` 或 `…`（带或不带引号）的示例，作为模板忽略。其余字段和类型必须合法，不容许重复键、未知字段或其他缺损。模板单独出现不能算有效答案；普通文本或 JSON 围栏中的省略式对象仍拒绝。
- 多个完整且非模板的答案（即使内容相同）、重复字段、错误类型、真正截断的 JSON、未闭合代码标记和无法识别的对象仍拒绝。代码块内出现的完整答案也参与歧义检查。
- 分类、精确行、实际读取和 fixture 未变的判定不改，不进行理由语义 judge。

## 回放与证据边界

验证同批 manifest/plan/ledger、已知终态及已核账费用，逐项绑定原 observation、原文、oracle 和 verifier 摘要后，回放全部可评分观察；预算耗尽与历史基础设施失败单列、不转成质量通过。原 verifier 与新派生 verifier 分开保存，逐项报告转移与拒绝原因。

回放只用于验证评分器修复。即使重新计算比例，也属于事后诊断，不能作为原冻结正式成绩、新付费评测或候选晋升证据。通过原创合成反例后固定解析器摘要，再执行完整保存回答回放，不按分类或定位成绩调阈值。
