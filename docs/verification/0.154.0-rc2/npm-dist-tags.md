# npm 默认安装通道同步

日期：2026-11-19。目标版本：0.154.0-rc2。此记录最初在推送发布 tag 前编写；本版本已正式发行，实际发布结果见末尾及[完整发行记录](official-release.md)。

用户要求发布 npm 包后，将最新发行包设为 `latest`。调整前公开 registry 的实际标签为 `latest=0.147.0-rc22`、`rc=0.154.0-rc1`；因此无标签安装与显式 rc 安装获取的版本不同。

## 发布行为

`scripts/publish_npm_willdeep.rb` 仍先核对版本及三个 GitHub Release 归档，再以 `rc` 发布包。成功后依次将 `rc`、`latest` 指向目标版本。发布失败不更新标签；标签更新失败以非零状态退出，并说明目标版本、失败标签及 npm 错误。

若该目标版本已经存在，则不重复发包，仍同步两个标签，支持修复上次只完成一部分的情况。`--dry-run` 不写包元数据、不发布、不更新标签。

发布前读取当前 `rc` 和 `latest`：任一通道已经指向较新版本时，过期任务不发布或移动标签。版本比较按项目的正式版本位及数字 rc 序号进行，避免 rc10/rc2 的 SemVer 字典顺序陷阱；未知版本或 registry 响应异常会阻止写入。自动发行与手动标签工作流共享串行并发组，防止两条工作流在检查和写入之间相互覆盖；并发组一致性检查已通过。新增回归同时覆盖已存在和未发布的旧目标，后者也不会先以 `--tag rc` 发布而回退通道。

npm 不提供两个 dist-tag 的原子更新：`latest` 失败时 `rc` 可能已经更新，流水线会明确失败。之后重试同一目标版本可补齐，不通过移动已有 Git tag 重发。

`.github/actions/ci-test/action.yml` 已接入发布脚本离线测试；手动 `npm-dist-tag` 工作流保留为恢复入口。此改动只涉及发布脚本、契约测试、CI 描述与文档，运行时产品代码和本机已验证二进制不变。
