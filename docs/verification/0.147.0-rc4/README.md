## 浏览器实际操作

1. 普通完成会话没有子会话空面板，也没有原手填创建表单。
2. 点击“需要处理 2”，展开列表，滚动并聚焦待处理区域；列出等待审批和模型不可用两个会话及各自原因。
3. 点击失败会话标题，页标题正确切换；错误横幅显示 `model_not_found` 与请求模型不可用的具体原因，保留诊断入口。测试凭据与私有路径替换为脱敏标记。
4. 在输入框触发 Enter 发送一条新的失败请求，不刷新页面即可看到具体原因；重新打开历史会话仍保留失败详情。
5. 发送明确创建子会话的请求，收到完整的标题、任务简报和只读/上下文选项。点击前实际 children 列表为空；提议卡没有 input/textarea。
6. 刷新父会话后，待开始提议仍存在；输入一段草稿，再点击“开始”。仅创建一个任务，提议消失，父会话和草稿保留。
7. 子任务真实调用 read_file 并完成，显示结果；清空测试草稿后点击“打开完整对话”，进入对应子会话，看到报告和返回父会话入口。
8. 使用另一请求 ID 重复确认同一提议，返回原 assignment，任务总数不变。
9. 375×812 手机视口下，点击待处理计数能聚焦列表；点击等待审批会话后进入正确聊天，审批按钮可见，手机侧栏自动收起。
10. 浅色桌面和深色手机布局均检查过实际 CSS 值；375px 宽度下页面无横向溢出，提议按钮可操作。
11. 切换中、英、日界面资源，提议操作和待处理入口相应变化；用户任务标题和简报保持原内容。
12. 再生成一个提议，点击“不创建”，待开始提议数变为 0，已有任务数仍为 1。
13. 最终检查未见浏览器 console error、已捕获的失败网络请求或预览服务错误。网络工具采用滚动缓冲，不据此声称完整网络历史零失败。

已保存桌面错误、桌面预填提议和深色手机提议截图。浏览器验收结束后已恢复桌面视口。停止独立夹具服务的操作被自动审批审核以“可能干扰运行中的任务”为由拒绝，服务仍保留运行，未改用其他方式强停；这项清理需用户确认后处理。

## 过程中的失败与修复

- 首次 Web build 因测试查询传入不支持的 `exact` 选项失败；修正测试类型后完整构建与 423 项测试通过。
- 首次 Rust CLI 编译因 Web dist 尚未生成、未声明的 tracing 引用和已部分移动的 frontend 借用失败。修正构建顺序、复用现有结构化日志方式、提前提取 Web 来源后，CLI 测试、构建和严格 Clippy 通过。
- 首次 workspace fmt 命令漏写 `--all`，未找到 targets；补全参数后的 workspace 检查通过。
- Ruby 中文文件检查曾使用默认 US-ASCII 失败，切换 UTF-8 后脚本检查通过。
