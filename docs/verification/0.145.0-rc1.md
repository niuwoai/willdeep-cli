### 完整 headless 目标回归与负载归因

修复后的完整 `headless_runtime` 目标（52 项，`--test-threads=1`）一次性运行结果为 **47 通过 / 5 失败**（746.96 秒）。5 项失败：

- `deferred_gates::runtime_yields_past_a_dependent_head_then_restores_the_original_question`（`deferred_gates.rs:104`，10 秒等待后 `parked` 仍为 `true`）
- `first_turn_titles_the_session_with_one_extra_provider_call`、`web_compress_command_is_served_by_the_harness_instead_of_the_provider`（均在 `process_cleanup.rs:56`，清理阶段进程映像枚举超出 10 秒期限）
- `retry_wait::root_retry_wait_is_observable_through_public_runtime_api`（`retry_wait.rs:124`，10 秒内 `Provider requests=0`，会话仍 `running`）
- `daemon_upgrade_drains_active_work_and_hands_off_without_loss`（`process_cleanup.rs:79`，同属清理枚举期限）

同期机器实测：`uptime` 负载均值 7.72→27.47，全机 893 个进程、148 个 `willdeep daemon run`（127 个来自 `~/.cargo/bin`，最长存活 2 天）。但 CPU 占用前列为 WindowServer 42%、Claude 渲染进程 29%、magpie 19% 等界面进程，**willdeep daemon 基本空转**；高负载来自本机桌面环境而非本项目进程，故不作为可清理项处理。负载下每次 `owned_until` 都要对全机约 900 个 PID 逐个查询映像路径，10 秒期限先于轮询收敛被耗尽。
