# 0.141.0-rc6：Git 诊断跨版本回归验收

日期：2026-11-04。变更基线：`e05d3a151d7f9fc81b360d6c3b769e89d1969889`（rc4），PR：[niuwoai/willdeep-cli#110](https://github.com/niuwoai/willdeep-cli/pull/110)。

## CI 失败与确认原因

rc4 的 [PR 流水线](https://github.com/niuwoai/willdeep-cli/actions/runs/41772670413) 和 [push 流水线](https://github.com/niuwoai/willdeep-cli/actions/runs/41772662632) head 均为上述提交。两套各有 macOS、Ubuntu、Windows、Linux x86_64、Linux aarch64 五项失败；WSL ABI smoke 各一项通过。十项失败均为 `snapshots_distinguish_plain_workspaces_repositories_and_broken_git_metadata` 对损坏 gitfile 错误的附加断言：

```rust
assert!(broken.contains("not a git repository"), "{broken}");
```

CI 实际得到：

```text
Git workspace discovery failed (exit status: 128): fatal: gitfile does not point to a valid repository: .../.git
```

从完整 PR 日志的 checkout 步骤核实，macOS、Ubuntu 和两个 Linux 架构使用 Git 2.56.0，Windows 使用 Git 2.56.0.windows.4。Windows 的退出状态显示为 `exit code: 128`，诊断相同。此前 `unwrap_err()` 及发现失败上下文断言都已通过，说明运行时正确拒绝了损坏元数据。失败来自 rc4 新增测试把本机 Git 的描述当成了跨版本固定文本。

## 修正范围

- 真实 Git 四态测试仍要求普通目录返回 `None`、仓库有快照、损坏 gitfile 返回发现错误、缺失目录返回启动错误。只将具体英文描述断言改为检查 `fatal:`，继续确认 Git 致命诊断被保留。
- 分类测试新增 `gitfile does not point to a valid repository` 负例，要求此错误不得降级为普通非仓库目录。原有权限、所有权、无效 gitfile、空诊断等负例全部保留。
- 运行时发现、诊断脱敏和手机任务实现没有变化；不忽略测试、不重试掩盖问题、不按退出码统一放行。
- 版本及当前文档同步到 `0.141.0-rc6`。rc5 已由独立 HOME 隔离改动使用，本分支不包含该改动；未合并其分支。
