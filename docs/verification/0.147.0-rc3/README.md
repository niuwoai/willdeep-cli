# 0.147.0-rc3 审批恢复与忙时反馈验收

日期：2026-11-07。状态：定向测试、隔离 Runtime/TUI/Web 验收和本机 Cargo 安装通过。用户明确要求“强制升级吧”后，停止排空等待命令，通过正常 shutdown 接口立即停止旧 Runtime，并启动已安装新版；首次交接后服务端版本为 `0.147.0-rc3`、PID `9794`、健康状态 `ok`，思考等级控制接口已确认可用。

随后用户的 fish 终端通过 Homebrew `0.145.0-rc4` 再次执行 upgrade，导致新版 Runtime 重新进入排空并拒绝新消息。按用户要求暂不修改入口；旧升级命令退出后，已再次停旧启新。当前 Runtime 为 `0.147.0-rc3`、PID `45197`、状态 `ok`，并通过该 Homebrew CLI 的只读控制请求确认可连接。重启前唯一运行中的 Task 已为 `cancelled`；未自动重发用户失败的输入，也未调用真实模型验证。

## 问题与现场证据

用户看到 TUI 提示待确认请求已收起，但审批卡长期没有恢复，后续问题也没有得到回答。经正常 Runtime 控制接口检查，同一会话仍处于 `waiting_approval`，原审批为 `parked=true`，三条后续 Turn 为 `queued` 且 `attempts=0`；这些消息均未设置暂缓或独立执行确认。因此只能确认这三条消息已被保存且仍在排队，不能由此断言所有 Web 提交均成功，更不能说当前模型已读取。

源码确认 `deferred_gates::tick` 在独立性判断前就收起审批。候选都无法独立执行时，没有任务启动，也就没有完成事件恢复原审批；原轮次等审批，后续轮次等原轮次，界面却隐藏了等待项。该行为在原真实 Runtime `0.145.0-rc3` 和已装 `0.147.0-rc2` 中均存在，单纯升级到 rc2 不能修复。

使用 `interaction.present` 只恢复原审批的可见性后，控制接口确认 `parked=false`，后续原轮次回到 `running`。本会话没有调用真实审批的同意、拒绝或取消接口，也没有删除真实排队消息；后续状态不能用来推断由谁处理了审批。

## 修复契约

- 只有候选通过独立性判断、经锁内状态复核且领取成功后才收起原审批。
- 候选依赖前一轮、分类未知/失败或领取失败时，保持原审批可见；没有独立任务运行时，恢复遗留的隐藏审批，包括队列已清空的情况。
- 保留原请求 ID、等待 sender、审批权限和队列消息；恢复展示不等同于同意审批。
- 独立任务运行期间维持原有收起行为，结束后恢复；停止抑制、升级排空和队列快照变化不可被绕过；单会话失败不阻止其余会话恢复。
- TUI/Web 忙时提交即时显示已收到的工具进展或等待原因；无证据时说明尚未收到新进展。
- 等待审批或回答时，普通文本 Enter 保留输入和附件并打开原请求；Cmd/Ctrl+Enter 可明确入队。成功只表示持久保存，当前模型尚未读取；失败保留草稿和幂等重试标识。

这次没有新增可靠的运行中模型插话协议：现有 `turn.steer` 只有内存收件箱且缺少完整的幂等交接和崩溃恢复，因此普通 Enter 仍保留 Runtime 持久队列。即时宿主状态反馈不等于模型立即回答任意问题。

按 `release-willdeep-cli` 技能仅执行本地安装和 Runtime 交接步骤。本机入口：

- Cargo：`~/.cargo/bin/willdeep`，版本 `0.147.0-rc3`，SHA-256 `959a3cbb7028b2918a85ba4b14a25d81f8138c78ec93180eb372b9e1b6901ce3`。

- rc2 备份：`~/.local/share/willdeep-cli/local-backups/0.147.0-rc2-20261106-233502/willdeep`，SHA-256 `ef3abf92c6163a9f1daf1af950df12f3e22f4016db5b5c2c6335b927aec4001b`。
- 更早备份：`~/.local/share/willdeep-cli/local-backups/0.145.0-rc4-20261106-225522/willdeep`。

Cargo 安装保留锁文件；上游已 yank 的 `chacha20 0.10.1`、`clipboard-win 5.4.1` 提示仍存在，本次未顺带升级依赖。

需要回退客户端时，可在退出新客户端后恢复 rc2 备份：

```bash
cp -p "$HOME/.local/share/willdeep-cli/local-backups/0.147.0-rc2-20261106-233502/willdeep" "$HOME/.cargo/bin/willdeep"
```

```bash
"$HOME/.cargo/bin/willdeep" --version
```

Runtime 回退需先确认没有人工等待、完成当前任务，并核对持久数据兼容性，再用回退二进制执行正常 `daemon upgrade --force --timeout 600`。本次未实际演练降级，不保证任意活动轮次跨重启恢复；`--force` 只跳过同版本判断，不是强杀任务。升级超时不会撤销旧 Runtime 的排空状态。
