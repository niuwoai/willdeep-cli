## 首次失败与修正

1. 第一轮 P2 Ruby 断言全部完成，但 Daemon 尚有最后的原子落盘操作，临时目录清理遇到 `Errno::ENOENT`，实际进程退出 1。这一轮不计为完整通过。夹具改为等待自己的 Daemon PID 真正退出，且只在清理全部成功后写入通过报告；重跑九组场景退出 0。
2. P0/P1 容量夹具的 50 秒 gate 在完成二十个任务入队前超时，导致以累计模型请求数检查四执行槽的断言失效。夹具 gate 改为 180 秒，产品执行槽与产品请求期限未改；后续重跑通过该容量场景，但父停止场景又触发等待超时，继续定位并重跑。
3. 新增共享只读用户打开测试在 macOS 使用临时目录符号链接路径，而 Runtime 持久化规范路径，严格绑定校验因此拒绝。测试夹具统一 canonicalize 路径；没有放宽生产路径或权限校验。
4. Core 全量以八测试线程执行时，两项既有测试分别触发 `offline_mock_timeout`（5 秒）与 `sink.flush(Duration::from_secs(10))` 断言。随后单独复测均退出 0：离线审查 11.05 秒、写入并发测试 8.69 秒。没有修改这两项测试或产品期限；本次不能宣称工作区在一次执行中全绿。
5. 初轮串行和两线程工作区测试曾因长时间执行而主动停止；通知屏障用例虽然报告超过 60 秒，后来实际输出 `ok`，没有据此判为永久死锁。
6. 容量后的父停止场景在旧构建中超过原有 60 秒仍没有派生任务。缩小复现中，同一个父 Turn 继续观察约 158 秒仍为 queued、attempts=0，没有模型请求；仅重启该合成 Daemon 后，同一个持久 Turn 在约 13.3 秒内开始派生。取样显示调度线程反复处理旧会话提示并竞争账本锁与同步磁盘；这是内存提示积压及空事务 I/O 的证据，不是永久死锁的证明。新实现有界合并同批重复提示、跳过空账本重写与重复屏障落盘、跳过错过的协调 tick，并在没有新增上下文的普通收尾避免额外 checkpoint；通知最终资格复核和持久提交仍保留同一控制锁边界。
7. 调度补强前五项 CLI 失败串行复测，账号事务锁、非法 Worker JSON 和后续阶段重试三项通过；`driver_advances_after_parent_returns_and_collects_each_leaf_once` 与 `dropping_host_cancels_workers_outside_the_display_snapshot_window` 仍触发原有十秒期限。`headless_runtime` 的八项失败分别涉及三项后台转向、Daemon 升级、根请求重试等待和三项 Web 流式场景。没有将失败拼接成一次全量通过，也未放宽用例或产品期限；最新源码的后续结果单独记录。
8. `87909e…` 缩小调度复现通过，但完整 P0/P1 容量回归前五组后退出 1：早入队的 CAP_CHILD 4 等待约 98 秒才启动，快照为 23 completed、4 running、3 queued，后入队任务曾多次先执行。周期扫描候选来自 HashMap 无序迭代；现已按会话最早未暂缓 queued Turn 的持久序号排序，并通过 28 项存储/调度测试及严格 Clippy。采样也显示全局 AgentStore 事件锁和实际持久化会影响吞吐，但未据短时样本推断永久死锁或底层文件系统病因；保留证据，未扩大本轮范围重构 AgentStore。
