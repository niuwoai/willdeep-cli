# 后台等待插话唤醒验收

开发基线：`62678b6`；版本：`0.105.0-rc3`。

## 修复范围

Runtime 主模型回复或达到轮次上限后，可能继续等待后台命令或监控任务。等待循环现在检查插话收件箱；有新指令时唤醒主模型，不要求后台任务先结束。检查不取走消息，读取仍由模型循环负责，任务退出时未读插话沿原逻辑交回客户端队列。

## 因果回归

两个隔离 Runtime 用例分别创建静默监控、后台命令，用文件闸门控制其退出：

1. 主模型达到 `max_turns=1`，等待持久检查点确认模型循环已经返回。
2. 后台任务保持运行且不产生新输出，调用真实 `turn.steer`，确认收到送达回执。
3. 检查模拟 Provider 收到以用户身份注入的消息，随后才释放后台文件闸门。
4. 后台结束后检查客户端正常完成、会话中该插话仅出现一次。

旧实现两个用例均在第 3 步超时，修复后两个用例通过。收件箱单元测试同时验证多次检查不会消费、改变消息顺序，排空后不会再次唤醒。
