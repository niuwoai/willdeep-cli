# 0.145.0-rc4：TUI Enter 即时反馈

## 范围

普通发送在第一次磁盘或 Runtime 控制操作前绘制用户消息；模型确认在第一次操作前关闭弹窗并显示目标模型与切换中反馈。保持原有串行执行顺序，运行中模型选择仍在本轮结束后生效。没有改动 Runtime 协议，也没有将整个输入事件循环改成后台状态机；控制操作完成前，后续按键仍排队等待。

源码验收使用独立工作树 `tui-first-enter-20261106`，分支 `fix/tui-first-enter-20261106`。本轮已获授权单独发布 rc4 并更新本机、h2、q4；审批引导不纳入本版。本文记录源码验证与测量条件，发布和部署结果另行取证。

## 真实终端验收方法

入口为 [Ruby PTY 夹具](../../../scripts/test/tui_enter_feedback.rb) 与[持久 VT 解码器](../../../scripts/test/tui_feedback_frames.mjs)。夹具创建独立 HOME、配置和工作区，只连接本机假 Provider，并启动该 HOME 专属的真实 Runtime。Runtime 控制代理保持健康检查正常，仅阻塞本次指定的控制操作约两秒；操作开始后才启用阻塞门，不把启动与模型列表加载耗时算作确认延迟。

前置操作先等到完成反馈，草稿先等到实际出现在输入区，再写入单次 Enter，用单调时钟记录完整同步更新帧结束的时刻。通过 `@xterm/headless` 还原画面，检查聊天区域中的反馈、关闭的弹窗和清空的输入区；不以累计 ANSI 字节里包含输入文本或模型名称作为通过依据。首帧阈值为 300 ms，并要求反馈发生在阻塞门放行之前。简洁 UI 的聊天区包括输入分隔线上方全部行，排除底部输入框与状态栏。

覆盖同 Provider、跨 Provider、模型失败、直接模型命令、鼠标确认、普通发送、运行中发送与失败恢复；确认重复 Enter 不创建额外轮次。失败路径检查持久化模型和 composer 恢复，底层单元测试另覆盖附件与回显认领。

## 夹具修正记录

初版夹具在退出时无期限等待 PTY 子进程回收，已停止该次运行、向该临时 HOME 的 Daemon 发送终止请求；后续先关闭 PTY 端点并限制回收等待。两次修复版初测未作为整体通过证据：一次在前一个模型切换尚未完成、草稿尚未显示时开始普通发送计时，另一次漏查聊天区最底部两行而误报忙时反馈超时。校正就绪条件、控制阻塞位置与聊天区坐标后，对最终二进制完整重跑。

独立审查补入配置诊断保护：TOML 错误不展开可能包含凭据的源行，其他失败保留原因并遮盖 URL；直接模型命令继续复用当前连接，配置暂不可读时仍可登记下一轮切换。

## 最终结果

旧版 rc3 的同 Provider 模型确认基线：控制请求阻塞 2010.46 ms，弹窗关闭并显示结果需 2636.02 ms，反馈发生在放行之后。修复版最终独立运行 8/8 通过，数据见 [results.json](results.json)：

| 场景 | 首帧反馈 | 控制请求阻塞 | 放行前出现 |
|---|---:|---:|---|
| 搜索命中模型后 Enter | 3.62 ms | 2019.43 ms | 是 |
| 模型切换失败 | 4.40 ms | 2002.92 ms | 是 |
| 直接 `/model <名称>` | 4.37 ms | 2010.72 ms | 是 |
| 跨 Provider 确认 | 2.82 ms | 2010.01 ms | 是 |
| 鼠标确认 | 41.16 ms | 2002.71 ms | 是 |
| 普通消息发送 | 10.08 ms | 2006.86 ms | 是 |
| 运行中消息发送 | 19.05 ms | 2004.31 ms | 是 |
| 运行中提交失败 | 19.25 ms | 2016.55 ms | 是 |

失败场景先显示正在切换/提交，放行后显示实际失败；模型失败保留原持久化模型，忙时失败恢复草稿且未发起后续 dispatch。重复空 Enter 未创建额外轮次。同 Provider、跨 Provider 和鼠标操作最终持久化的 profile/model 也已检查。

- TUI 单元测试：425 passed、0 failed、2 ignored。两项忽略项为既有的手动确定性流式渲染基准及节奏控制的流式显示测量，没有计为通过。
- CLI 构建通过；`cargo clippy -p willdeep --all-targets -- -D warnings` 通过。
- Web 嵌入产物构建通过（`yarn build`），用于 Rust CLI 的嵌入资源；本次没有修改网页行为，不以浏览器预览验收原生 TUI。
- Rust 格式、补丁空白、Ruby 与 Node 语法、VT 解码器完整帧/行坐标检查通过。
- 版本一致性检查通过，目标 `0.145.0-rc4`。
- 上述时延测量发生在源码提交前。后续提交、发行与安装状态以 [GitHub Release](https://github.com/niuwoai/willdeep-cli/releases/tag/v0.145.0-rc4) 和各环境的安装回执为准，不将源码测试通过等同于部署完成。

这些数字来自 macOS 上隔离 PTY 的完整输出帧，证明首帧反馈不等待被阻塞的控制请求；不是物理显示器绘制耗时或全平台性能保证。控制操作仍串行执行，期间后续按键会排队；没有宣称完整事件循环已经后台化。
