# 延迟命令后台执行与插话验收

日期：2026-10-20。开发版本：0.108.0-rc1；保留前一项项目会话启动选择功能。

## 执行与界面

- `sleep 240; cd ...` 等以至少 30 秒字面整数等待开头的命令，即使未指定后台开关或传入 false，也会整体交给已有后台执行器；不拆分、不重写、不重新启动原命令。
- 保留原审批、围栏、工作目录、执行顺序、显式超时和任务总预算。省略超时时默认包含等待时间并给后续步骤留 60 秒，整体仍受 600 秒上限约束。
- 短等待、动态等待参数、非首条命令内的 sleep 不触发转换；验收命令和受精确命令白名单约束的 Worker 保持同步执行，不能把启动成功当作验收通过。
- TUI 展示转入后台的原因与秒数。模型结束本轮回复并进入后台等待后，状态区和输入区明确提示可继续输入，普通文本回车后自动发送；后台任务继续运行。队列/附件面板打开时暂停自动发送，附件和命令继续沿用原队列规则。
- Runtime 仅增加数值型 `background_delay_seconds` 提示，不把成功命令的私有输出带到公共事件。后台完成结果沿用原事件投递和会话恢复机制。

## 实际联调

`ruby scripts/delayed_command_tui_verify.rb <开发二进制绝对路径>` 使用真实 PTY、TUI 和 Runtime，配合隔离 home、工作区与本机模拟 Provider，执行真实 30 秒 sleep：

1. 模型发起 `sleep 30; cd nested && ...`，明确设置 `run_in_background: false`。
2. 进入后台等待后，自动化在实际输入框输入插话并按回车，未调用 API 代替这次 UI 操作。
3. 模拟 Provider 收到该用户消息时，原命令尚未结束、结果文件尚未创建。
4. 原命令继续执行，完成输出随后交给模型，文件仅一行、命令仅发起一次，插话在会话中仅保存一份，界面提示可见。

实测上述断言全部通过，脱敏结果见 [tui-report.json](tui-report.json)。脚本同时保存 ANSI 原始输出和 JSON/Markdown 报告到其输出的临时目录；结束时仅停止该隔离 home 的测试 Runtime，不升级或中断用户真实 Runtime。

Runtime 集成测试另行验证：模型循环到达轮次上限后，自动后台命令仍运行；插话被模型读取时前置 sleep 尚未结束，随后命令只执行一次。原 monitor 与显式后台命令的两项插话回归也通过。
