# 0.143.0-rc2 Windows 栈溢出修复验收

日期：2026-11-04。平台：本机 macOS arm64。状态：0.143.0-rc1 的 Windows CI 栈溢出已定位并修复；本次提交尚未发布，未执行的平台见文末。

## 根因

Windows CI 的 `CI / test (windows-latest)` 在 `daemon::mobile_gateway::tests::message_send_with_a_workspace_path_opens_a_session_there` 上以 `STATUS_STACK_OVERFLOW`（`0xc00000fd`）退出。用 `RUST_MIN_STACK` 在本机二分：

- 修复前，该测试在 1.5 MiB 栈下溢出、2 MiB 通过；`Cli::try_parse_from(["willdeep"])` 单独就需要 1.25–1.5 MiB 栈。
- 该调用来自 `magpie_integration::pin_new`，`session_create` 在调用它时已在同一线程栈上叠加 daemon 请求与测试框架的帧；Windows x64 的 debug 帧更大，超过 libtest 测试线程默认的 2 MiB。
- 同类调用还存在于 `daemon/deferred_gates.rs`、`web/setup.rs`、`web/schedules.rs`、`web/runtime_chat.rs`：都只为取得默认选项而解析完整 argv 命令树。

## 修复

- 新增 `Cli::bare()`，直接构造 clap 对裸 `willdeep` 调用产生的值（含 `WILLDEEP_CONFIG` / `WILLDEEP_API_BASE` / `WILLDEEP_API_KEY` / `WILLDEEP_MODEL` / `WILLDEEP_LANGUAGE` 环境变量默认与 `listen` 默认值），不构建命令树。
- 上述 5 处 daemon/Web/Magpie 调用点改用 `Cli::bare()`；真实 CLI 入口仍走 clap。
- 新增 `main_tests::bare_cli_matches_clap_defaults`，比较 `Cli::bare()` 与 `Cli::try_parse_from(["willdeep"])` 的完整调试输出，防止 clap 默认值变化后两者漂移。
