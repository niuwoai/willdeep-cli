## 失败历史

- 首轮 `cargo fmt --check` 发现新增测试格式尚未统一，已执行格式化。
- 首轮测试编译失败 `E0061: method takes 1 argument but 3 arguments were supplied`：新增审批捕获测试误把 `ApprovalRequest` 元组拆成三个参数；已改为元组传参。
- 独立静态审阅发现两项边界：跨区滚轮合并越过较早暂存按键、原生选择期间粘贴不可见。已修复并增加针对性原生与真实 PTY 检查。
- PTY 第 1、2 轮在长菜单滚动检查超时；第 1 轮暴露了只等待通用菜单标题的夹具竞态，已改为等待具体问题。继续检查实际终端帧后确认 Runtime 把选项限制为 12 项，40 行窗口中正文并未溢出，因此滚轮不应移动。夹具改用 18 行短窗口形成真实溢出，保留失败帧并重跑。
- 第 3 轮长菜单检查已通过，但结束回复因保留阅读锚点而不在当前可见行，夹具等待超时；改为显式返回最新，并恢复足够的正文窗口后检查回复。
- 第 4 轮 full 全部通过，compact 的原生选择提示首字母为大写，夹具大小写敏感导致超时；改为大小写无关识别。第 5 轮两种布局全部通过，清理检查也全部通过。

## 隔离与边界

运行夹具使用全新 HOME、WILLDEEP_HOME、XDG、TMP 与工作区，子进程只继承明确允许的环境变量。所有模型输出来自回环合成 Provider；鼠标事件和 OSC 52 剪贴板输出只在自有 PTY 内捕获。清理只停止夹具自己的 Runtime、PTY、VT 解码器和 Provider；不操作用户现有终端、daemon 或系统剪贴板。

真实 PTY 验证应用的键鼠分发及终端控制序列，不代表 MuseTerm 或所有宿主的备用屏历史保存行为已实机覆盖。应用无法按列改写宿主保存的整屏历史；截图中重复旧侧栏的宿主侧根因未在本轮宣称完全消除。未覆盖其他操作系统或真实模型。
