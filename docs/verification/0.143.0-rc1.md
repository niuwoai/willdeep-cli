# 0.143.0-rc1 完整子会话 P1 验收

日期：2026-11-04。平台：本机 macOS arm64。状态：P1 已实现并整合到 `origin/develop` 的 0.142.0-rc1（Magpie 社区 Agent）之上；本机功能与工程回归见下表，本次提交尚未发布，未执行的平台和后续阶段见文末。

## 实现范围

- `context=fork`：只继承父会话已完成 Turn 的不可变消息前缀，校验轮次边界、压缩代次与工具调用闭合，复制内联附件，清空 Goal、计划、压缩/执行检查点、已读标记与运行游标；摘要只在覆盖前缀内保留。
- `workspace_mode=worktree`：在取得执行槽后创建独立 Git worktree，支持 `head` 与 `snapshot` 基线；snapshot 冻结已跟踪修改并复制未跟踪文件，记录补丁摘要、未跟踪数与父目录脏状态。父目录不被子会话修改，任务结束保留 worktree/分支，不自动合并、提交、推送或删除。
- 受限模型覆盖：只接受父 Session 的 Provider 配置中可用且具备工具/图片能力的模型，按目标模型写入真实上下文窗口；未知模型被拒绝。
- 可写 worktree 子会话开放 Worker；父会话与子会话共享进程内家族调度器、并发/排队策略和按记录 ID 去重的家族用量预算。只读子会话继续禁止 Worker、Shell、写入、MCP/插件副作用与继续派生；所有子会话都不能创建下一层子会话。
- CLI、TUI 与 Web 暴露 P1 参数和状态；worktree 子会话不在全局 Workspace 白名单中，Web 与 TUI 通过父会话/目标路径回退授权和切换，任务卡显示工作树分支与基线。

## 隔离端到端场景

入口：`scripts/verify_child_sessions.rb`，使用临时 `WILLDEEP_HOME`、合成工作区与本机 TCP 假模型，排除继承的 Provider 凭据和代理配置，不读取个人凭据。

1. 模型派生、`fresh` 隔离、真实 `read_file`、独立 root Agent、父空闲回报与持久消费。
2. 并发幂等、同键异参冲突、关系归属、单层派生及未支持模式拒绝。
3. 续做保留会话并创建新任务；成功任务不能冒充失败重试。
4. 真实 CLI 创建、列表、查询、续做及终态停止入口。
5. 实际执行边界拒绝 Shell、写文件、Worker、MCP、递归与伪造宿主来源。
6. 两个父会话共享宿主四执行槽、十六排队、拒绝溢出并逐项释放。
7. 主动停止父会话不取消已受理子任务，结果待处理且不自动拉起。
8. 同目录重启保留任务结果和停止抑制，不重复执行模型。
9. fork 复制已完成前缀与内联附件、排除后续 Turn、清空执行状态并保持只读。
10. worktree 在取得执行槽后创建，HEAD 与 snapshot 基线隔离，父工作区零改动，Worker 计入家族用量。
11. 模型覆盖只接受父 Profile 可用模型，按目标模型能力写入真实窗口并拒绝未知模型。

## 验证过程中的修正

- 整合到 `origin/develop` 后，上游给 `RuntimeSession` 和 Core Session 增加了 `magpie_integration` 字段。新建子会话的 `RuntimeSession` 与 Core 现在都继承父会话的集成来源，避免父会话使用临时 `magpie-cli` Provider 时子会话丢失来源或错误回退到同名 TOML 档案。
- 全量回归后的文件规模检查发现 `crates/willdeep-cli/src/web.rs` 因整合达到 3,091 行，超过 3,000 行硬限制。把会话工作区授权与文件指纹缓存迁到 `crates/willdeep-cli/src/web/session_access.rs`；只移动既有函数并补充测试导入，行为不变，拆分后 `web.rs` 为 2,987 行、新模块 117 行。
- 浏览器验收发现真实 Web 授权缺口：worktree 子会话的 workspace 位于 `$WILLDEEP_HOME/worktrees/children/`，不在 Web Workspace 白名单，`session_detail`、列表、事件流、聊天和审批入口返回 400。修复位于 `crates/willdeep-cli/src/web.rs` 的调用点与 `crates/willdeep-cli/src/web/session_access.rs` 的授权模块：自身 workspace 未注册时回退到 `parent_session_id` 对应父会话的已登记 workspace，worktree 子会话审批上限固定为 `workspace_write`，子会话列表与详情仍以父项目 workspace 组织；随后浏览器完整通过。
- TUI PTY 验收发现 `/session children open` 与 `/session children parent` 对 worktree 子会话失败：`session_commands::switch` 要求同一 Workspace，而子会话 workspace 是独立 worktree。新增只供子会话导航使用的 `switch_related`，在 `ensure_runtime_session` 后切换 Runtime 工作区、按需激活已登记的父 Workspace、重启事件跟随器，并保留普通 `/session` 的同 Workspace 限制。会话来源行同时区分只读调查与可写工作树，会话选择器区分只读/可写子会话。
- 全工作区回归首轮发现 `usage_ledger::tests::serialized_keys_are_exactly_the_spec_set_and_carry_no_content` 仍按 23 键断言，P1 新增的 `family_session_id` 未登记。已把该可选家族根字段纳入 24 键断言并更新 `docs/USAGE_LEDGER.md`；字段带 `serde(default)`，旧行缺省为 `null`，Xedit 的 Swift 读取端按未知键忽略。Xedit canonical 规范的字段同步属于跨仓后续，本轮未修改 Xedit。
- 并行全量回归还暴露了 `harness::delegation::tests::delegation_harness_rebuilds_main_rules_without_executing_extensions` 的临时目录清理竞争：`drop` 后共享账本写线程仍可能在创建 `usage/`，导致 `remove_dir_all` 偶发 `DirectoryNotEmpty`。已先调用 `flush_all` 并在有界时间内重试删除；该用例连续 30 次通过。
- 默认并行回归还出现过两处测试时序失败：`agent::recovery::ownership_tests::rejected_parent_execution_does_not_claim_or_interrupt_its_team` 的 `claim()` 返回错误，以及 `usage_ledger::tests::the_shared_writer_thread_serializes_concurrent_submissions` 的 `flush(10s)` 超时。前者单独连续 30 次及 10 进程并发 50 次均通过，后者在串行全量中通过；两者都不属于 P1 新增路径，本轮未改动其生产逻辑。最终判定使用串行全量回归，不把并行时序失败说成产品通过。
- 第一次 TUI 断言是假阳性：父会话任务卡本来就会展示 `CHILD_REPORT`，未切换也能命中。已改为同时要求 `Session switched`、目标会话 ID 与 `Task from`；窄屏详情按可见的 `Branch:` 前缀断言，不再依赖滚出屏幕的字段。
- 浏览器只读检查最初只断言背景不是白色；现通过 CDP 模拟 `prefers-color-scheme: dark` 并检查背景/文字亮度，避免浅色主题误通过。父会话或子会话忙碌时，打开相关会话会按既有设计在新标签页保留原聊天流，脚本分别验证同标签页与新标签页两条分支。
- 最终重跑时宿主同期在跑 Xcode 构建、swap 接近耗尽，Web 默认并行跑出现 3/41 项 5 秒超时失败、2 worker 跑出现 7 项；单文件隔离运行通过，单 worker 串行全量 44 个文件 / 320 项全部通过。未修改测试超时、断言或产品代码，最终结果以 `yarn test --maxWorkers=1` 记录，并在上方 Web 行注明宿主负载。
- 同一负载下浏览器驱动首次在 10 秒内未等到 headless Chrome 的 `DevToolsActivePort`。仅把本地临时驱动脚本的启动等待放宽到 60 秒，15 项断言未改，随后完整通过。
- 上述修正没有放宽工具权限、审批档位或子会话边界；Web 回退只使用父会话已登记的同一项目 workspace，未把 worktree 路径加入全局白名单。
