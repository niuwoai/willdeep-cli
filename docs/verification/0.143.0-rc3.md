# 0.143.0-rc3 Windows Magpie 传输测试超时修复验收

日期：2026-11-05。平台：本机 macOS arm64。状态：Windows CI 上 `provider::magpie::tests::integration_transport_has_no_proxy_or_redirects_and_pins_localhost` 的 `Elapsed(())` 超时已定位并修复；本次提交尚未发布，未执行的平台见文末。

## 根因

- Windows CI（PR 与 push、以及 develop 的 0.142.0-rc1 基线）都在该测试上失败：父测试在 10 秒内等不到子进程连接 `127.0.0.1` 回环监听，`upstream.accept()` 超时并在 `magpie.rs:137` 以 `Elapsed(())` 退出。
- 子进程由 `Command::env_clear()` 启动，只显式设置 `WILLDEEP_MAGPIE_TEST_URL` 与代理变量。Windows 的加载器与 socket 初始化会从环境读取 `%SystemRoot%` 等系统变量；环境块被清空后，子进程在建立连接前就失败（Rust 官方 issue #114737 记录了 `env_clear` 在 Windows 上不可用的同类问题）。
- 父测试当时只对 `accept()` 的超时调用 `unwrap()`，子进程的 stderr 与启动错误没有进入失败信息，只能看到 `Elapsed(())`。

## 修复

- 仅在 Windows 上，`env_clear()` 之后保留 `SYSTEMROOT`、`WINDIR`、`PATH`、`TEMP`、`TMP`（存在时才设置）；Unix 行为不变，代理隔离与 localhost 固定断言保持不变。
- 等待连接超时时，父测试改为等待子进程并输出其 stderr，或输出启动/任务错误；正常路径的断言不变。
