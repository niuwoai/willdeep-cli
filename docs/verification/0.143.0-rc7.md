# 0.143.0-rc7 发行验证修复

本记录为 rc7 提交前快照，公开发行与本机/远端安装结果需另行记录。

## 修复范围与原因

- rc6 的 Intel runner 已成功完成 x86_64、aarch64 两次编译，但 `lipo -verify_arch x86_64 arm64 willdeep` 把文件名解释为架构参数而失败。rc7 改由独立 Ruby 脚本读取 `lipo -archs` 并严格比较两个预期架构。
- rc6 的 Windows 验证为 1275 通过、4 失败、4 忽略。失败发生于真实 MCP/Python 请求等待和 64 个任务取消后的持久化收尾，相关实现从 rc5 到 rc6 无变更；现有证据支持测试负载下的超时波动，尚未证明唯一根因。
- 官方公开仓库 Windows 标准 runner 为 4 CPU；仅将 Windows libtest 用例并行度降为 2，保留全部测试、用例内部并发和 Clippy。macOS/Linux 继续默认并行，不调整产品超时或跳过测试。

历史依据：[rc6 Release 流水线](https://github.com/niuwoai/willdeep-cli/actions/runs/41885876919)、[官方标准 runner 资源](https://github.com/github/docs/blob/main/data/reusables/actions/supported-github-runners.md)。rc5、rc6 标签保留原指向。

## 本机已执行

- Clang 生成的真实 fat Mach-O（x86_64 + arm64）通过；thin Mach-O（只有 arm64）及缺失文件被拒绝。
- 插件网关完整模块：9 项通过，0 失败；工作流取消专项：1 项通过，0 失败，64 任务收尾约 4.52 秒。
- `cargo clippy -p willdeep --all-targets -- -D warnings`：通过。
- Web TypeScript/生产构建通过；npm 安装契约 6 项、37 断言通过。
- 版本守卫接受 rc7，四个工作区包、两个内部 runtime 依赖、Web/npm、产品/架构头与 CHANGELOG 一致。
- CI YAML 验证显示所有平台仍执行完整工作区测试，Windows 额外传入 `--test-threads=2`；发行合包仍是两个 Apple Darwin 目标，版本发布门禁保留。

## 验证边界

本机专项在 macOS 执行，不能替代 Windows 原生验证；Windows 减少用例并发的稳定性仍由本次完整 CI 与 Release 验证。rc7 尚未在此快照中公开发行或完成三机安装，后续资产摘要、Homebrew、Runtime、h2/q4 备份与健康检查独立核验。
