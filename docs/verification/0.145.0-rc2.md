# 0.145.0-rc2 Windows 验证修复与发布记录

日期：2026-11-06。项目阶段：既有项目迭代。本记录是 [`0.145.0-rc1`](0.145.0-rc1.md) 的补丁版本，只处理 Windows 验证阻塞。除 Windows 的内置配置服务启动期限外，产品代码与 rc1 相同；rc1 的静态、Runtime、客户端与浏览器证据继续有效，本记录不重复。

**结论：rc2 源码 `01a75602` 的完整 CI（Windows、macOS、Ubuntu、Linux x86_64、Linux aarch64、WSL）全部通过，运行 `42058388908` 结论为 success。** 发布由 tag `v0.145.0-rc2` 触发的 Release 工作流完成，`Publish GitHub Release` 与 npm 发布以该运行的 verify 结果为准。

## rc1 的失败事实

`v0.145.0-rc1` 推送后，develop、main 与 tag 三次 CI（`42044107204`、`42044107620`、`42044107102`）都在 `test (windows-latest)` 失败；Release 运行 `42044107421` 的 Verify release 同样失败，`Publish GitHub Release` 与 `Publish npm package` 因 `needs: verify` 被跳过。**没有创建 GitHub Release，也没有发布 npm 包。**

失败集中在两个新增测试：

| 用例 | Windows 错误 |
|---|---|
| `configuration_host::tests::custom_path_preview_save_and_receipt_replay_preserve_default_and_backup` | `assertion failed: description.contains(path.to_str().unwrap())` |
| `daemon::child_sessions::store::tests::rejected_schema_one_transaction_leaves_the_original_retryable` | `replace child session ledger: Access is denied. (os error 5)` |

## 根因

- 配置宿主在构造时把路径固定为 `std::path::absolute` + `canonicalize` 的结果。Windows 的 `canonicalize` 会返回带 `\\?\` 前缀的 verbatim 路径并展开短名，测试却拿 `std::env::temp_dir()` 拼出的未规范化路径做子串比较，因此必然不等。
- 子会话账本用 `MoveFileExW(REPLACE_EXISTING)` 原子替换。Windows 在目标文件仍被打开时拒绝替换，而测试为验证“被拒绝的事务不改动原文件”一直握着 `File::open` 句柄，直到重试迁移时才失败。Unix 的 `rename` 覆盖打开文件不受影响，所以本机单测一直是绿的。

这两处是测试自身的平台假设，不是产品逻辑错误；修复只改测试。

## rc2 复测暴露的 Windows 冷启动问题

修复上述断言后，rc2 首次 Windows CI（`42051907349`）改为在 `configuration_host::tests::custom_path_preview...` 的 `plan` 阶段失败：

```
called `Result::unwrap()` on an `Err` value:
Io(Custom { kind: Other, error: "bundled configuration service unavailable" })
```

同一轮里其他配置宿主用例（同样启动 Ruby MCP 服务）全部通过，Windows runner 也确实预装了 Ruby 3.3。判定为首个配置用例的冷启动成本：首次写入整包插件资源并拉起 `ruby.exe`，需要支付新文件的按访问扫描；10 秒的启动握手预算在慢 runner 上不够用。该问题是真实产品路径（Windows 用户首次编辑配置）而不仅是测试问题。

## 修复

| 文件 | 改动 |
|---|---|
| `crates/willdeep-cli/src/configuration_host/tests.rs` | 审批描述断言改为与 `canonicalize` 后的规范路径比较 |
| `crates/willdeep-cli/src/daemon/child_sessions/store.rs` | 迁移重试前 `drop(original)`，释放测试持有的账本句柄 |
| `crates/willdeep-cli/src/configuration_host.rs` | `CONFIG_SERVICE_STARTUP_TIMEOUT_SECONDS`：Windows 30 秒，其他平台保持 10 秒 |

Windows 的期限调整经用户明确同意后实施，只影响内置配置服务的 `initialize`/`tools/list`/工具调用预算；服务连接后复用，不改变其他平台行为。

版本元数据同步为 `0.145.0-rc2`：workspace 版本、两个 runtime 依赖钉、`Cargo.lock` 四个工作区包、Web/npm、安装清单 version/tag、`PRODUCT_OVERVIEW.md`、`docs/ARCHITECTURE.md` 与 CHANGELOG；`ruby scripts/check_release_version.rb 0.145.0-rc2` 通过。
