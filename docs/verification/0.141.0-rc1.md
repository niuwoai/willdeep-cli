## 隔离 Runtime 与 PTY

专用入口：`scripts/verify_workflow_runtime.rb`。完整运行输出 JSON + Markdown；默认输出目录是 `build/verification/workflow-runtime/`，属于忽略的本机验收产物。

```bash
ruby -EUTF-8 scripts/verify_workflow_runtime.rb
```

运行前需要已构建的 `target/debug/willdeep`，可用 `WILLDEEP_BIN` 指向另一份已构建产物。终端验收通过 Web 依赖中的 `@xterm/headless` 解释真实 PTY 输出，需要先安装 Web 依赖。`--serve` 保留回环 Web 预览；停止后只清理本次临时 Runtime。`--skip-tui` 会把终端明确标记为跳过，不算完整验收。

| 场景 | 实际检查 |
| --- | --- |
| 同轮管理与派工 | list→create→派出旧 Worker→update→bind→派出新 Worker；旧 Worker 保留原正文/模型，新 Worker 使用更新后的正文/模型 |
| API 准入与幂等 | validate/save/run 后完成依赖流水线；重复 request 返回同一运行，不重复执行 |
| JSON 拒绝与重试 | 假模型首次返回非法 JSON，源运行失败；重试生成关联的新运行并完成，源历史仍为失败 |
| 整组停止 | 活动叶执行期间 stop，运行收敛为取消，后继不执行 |
| 聚合确认 | 终态聚合先保存到父会话，再确认；运行保存 acknowledged |
| 对话工作流 | 父模型调用 schema→save→run；父最终回复已持久保存时阶段仍在运行；后继随后完成，持久会话投影只有一张对应运行卡 |
| 逐项流水线 | 慢项调查被阻塞时，快项已被 Runtime 持久确认为核验完成；释放慢项后完成汇总，四个调查/核验叶各调用一次 |
| 同目录崩溃恢复 | 只强制终止本次隔离 daemon；同 home 重启将未知在途副作用记为中断，不自动重放；显式 resume 新建运行、复用成功节点、保持原定义/模型；新普通派工使用已更新目录 |
| 共享调度 | 同一父模型响应派出 1 个普通 Worker 与 2 个工作流，各图 9 个叶；配置上限 3 并发/2 排队，实际观测队列饱和和三类任务同时执行；19 个唯一 request/Agent 全部只执行一次。产品默认上限仍为 8/64，由原生测试另验 |
| 真实终端 | 独立 Ruby 进程驱动 110×34、42×22 PTY，各执行 list/get/history；验证 Left/Delete 编辑、Enter、PageUp/PageDown 和 Ctrl-C；详情包含复用来源。六项通过，未产生新模型轮次 |

终端保存 `tui-report.json`、`tui-report.md`、`terminal.ansi`、`terminal-evidence.json` 和逐次渲染文本。验收按每个真实同步刷新帧检查短暂回执，退出时持续读取 PTY，避免验收自身堵塞子进程输出。没有检查实体终端窗口。
