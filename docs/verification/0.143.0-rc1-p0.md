# 0.143.0-rc1 完整子会话 P0 阶段验收

日期：2026-11-04。平台：本机 macOS arm64。状态：P0 阶段的原始验收记录，代码随后继续完成 P1，并以 `origin/develop` 的 0.142.0-rc1（Magpie）为基座重新回归；最终结果见 [P1 验收记录](0.143.0-rc1.md)。本文保留 P0 当时的证据与边界，不把阶段结果当作最终整合结果。

## 实现范围

- 完整子会话使用独立 Session、root Agent、历史和 Turn；专业 Worker 保留原有运行与报告链。
- 仅支持 `fresh`、`shared_read_only`；主 Harness 重新装配规则，简报与结果按宿主协调数据输入。
- 持久只读上限覆盖续聊、重启、审批偏好变更及工具执行入口；P0 禁止 Shell、文件写入、Git 进程工具、MCP/插件、Worker、工作流和继续派生。
- 创建、续做、重试与停止统一走 `session.child.*`；请求幂等、固定身份、受理点、停止代数、4 执行槽 / 16 排队、结果 outbox 与唤醒批次保存在协调账本。
- 通知只有出现在父会话持久的 HostInstruction 历史中才确认消费。停止父会话保留已受理子任务与待处理结果，并抑制自动续推。
- CLI、TUI 与 Web 提供完整聊天入口；Web 子任务接口仅本机开放，公开分享拒绝子会话并过滤父聊天中的私有宿主消息。

## 隔离端到端场景

入口：`scripts/verify_child_sessions.rb`，使用临时 `WILLDEEP_HOME`、合成工作区与本机 TCP 假模型，排除继承的 Provider 凭据和代理配置，不读取个人凭据。

1. 父模型调用 `start_session`；子会话不继承父私有历史，用真实 `read_file` 读到合成证据，拥有独立 root Agent，终态报告落盘后父会话安全接收并确认消费。
2. 四个并发相同请求返回同一 assignment/child；同键异参、跨父读取/续做、递归、fork 和 worktree 模式被拒绝。
3. 续做保留同一子聊天并创建新任务；成功任务不能作为失败重试。
4. 真实 CLI 完成创建、列表、查询、续做及终态停止；续做保留 child 身份并创建新 assignment，停止已结束任务保持幂等。
5. 假模型真实尝试 Shell、创建文件、派 Worker、调用 MCP 和递归派工，持久工具回执均明确记录只读拒绝；合成文件未改变。外部 Worker API 及伪造宿主 origin 也被拒绝。
6. 两个父会话共用四个执行槽，十六项等待排队，第 21 项被拒绝；释放后 20 项全部结束。
7. 父 Turn 停止后，已受理子任务继续完成，父会话未被自动拉起，结果仍待处理。
8. 同一临时目录重启 Daemon，结果身份与内容不变，停止抑制保留，没有额外模型执行。

协调单测另外覆盖受理前取消、已受理但未入队时父会话删除、唤醒 Turn 已落盘但账本指针丢失、等待人工输入占槽、旧唤醒执行前失效、重试替换通知和未知 schema 拒绝覆盖原数据。分享回归覆盖旧子会话 token 的读写拒绝，以及父分享过滤 HostInstruction。

## 验证过程中的修正

- 首次 PTY 断言因多任务列表标题滚出屏幕而超时，已改为检查实际可见 assignment 与打开命令；最终宽窄复验通过，并增加父子两端 Turn 不变检查。
- Harness 新夹具最初使用不被现有配置校验接受的 verifier 样例，随后改为合法但不会执行的验证命令；真人输入断言按真实 `Message::user` 语义改为 `Some(OperatorInput)`。第一次完整 CLI 单测为 1,268 通过、1 失败、4 忽略；修正后完整工作区为 2,340 通过、0 失败、11 忽略。两个问题均位于新增测试数据与断言，未以放宽生产权限或更改消息来源语义解决。
- 文件规模脚本首次因当前 Shell 默认 US-ASCII 无法解析 Unicode 路径而退出；显式 `ruby -EUTF-8` 后通过，未为此修改生产代码。
