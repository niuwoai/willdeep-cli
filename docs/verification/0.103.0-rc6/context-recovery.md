# 自动与手动上下文压缩修复

版本：0.103.0-rc6。隔离分支 `codex/context-compression-recovery`，基线 `03d0a7e`。尚未覆盖本机安装、运行中的 Runtime 或 h2；未修改冻结 RSI 程序、题库、回答、评分与账本。

## 已确认故障与修复

本机失败记录表明两次失败分别需要 108178 / 108328 token，但在工具 schema 与输出预留后只剩 106943。读取会话只统计类型、长度与重复摘要，不输出消息内容：压缩代数已为 1，真实用户输入 12 条共 755 字符；宿主提示 47 条共 255723 字符，其中多组完全相同。原压缩器将全部 user-role 的宿主提示永久保留，导致生成摘要后仍超限。

对同一失败会话只读计算受保护部分：消息 60 → 28，按生产同口径内容估算 105056 → 45786 token，真实操作员输入仍为 12 → 12。此数字只包括受保护部分，不冒称是新模型实际输入用量；未修改客户会话或发模型请求。

新实现仅在上下文投影中对完整字段均相同的 HostInstruction 去重，保留最后一次及其顺序；不去重真实用户输入、系统规则或不同宿主指令。手动压缩成功后才替换持久会话；自动压缩仍不改持久原文。工具参数/结果保持协议配对，未知工具效果及其新授权防重放保护继续原样保留。

另外修复回传思考内容未计入容量估算、短但过大会话被错误跳过、巨大近期尾部不进入摘要、手动压缩未检查结果容量，以及自动压缩先发成功事件再报超限。现在只有最终容量检查通过才报告完成；不可压缩的真实指令过大时明确失败，保留原件。

摘要原料采用实际序列化后的上限，单块路径使用已裁剪消息；JSON 转义、附件、参数及思考内容均受限。摘要输入为带显式截断标记的不可信派生片段，可能不是完整 JSON，不能当作原始执行证据；原始用户指令和未知效果仍从原消息保留。
