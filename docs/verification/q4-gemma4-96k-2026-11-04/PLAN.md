# q4 Gemma 4 对比测试计划

日期：2026-11-04。项目阶段：既有项目的外部模型服务验证，不修改 WillDeep 应用实现。

用户已授权顺序测试：**先 Gemma 4 12B QAT，再 Gemma 4 26B-A4B Q3**。继续采用此前 q4 基线的 **96K 单路、72K 输入冷热测速**；12B 基线通过后评估配套 MTP。测试结束先恢复已有 Qwen3.6-35B-A3B 服务，长期模型选择依据结果另定。

## 基线与候选

- 已有基线：Qwen3.6-35B-A3B UD-Q2_K_XL，98,304 上下文 / 单槽。72K 冷输入 prefill 约 1,507 tok/s，decode 约 70 tok/s，首个非空输出约 49 秒。见 [基线报告](../q4-qwen36-moe-96k-2026-11-04/README.md)。
- 第一候选：Google `gemma-4-12b-it-qat-q4_0.gguf`，6,975,879,296 bytes；SHA-256 `93567e57a8fe10b23569b9d9ec38cd005deedf71e29477c421a4b83f418a538b`。
- 12B 配套 MTP：Unsloth `mtp-gemma-4-12B-it.gguf`，253,708,800 bytes；SHA-256 `fcb35dea42c71333db904cee11baac525c9ef872818ee3753f6cb156f3c6f4f6`。跨仓库兼容性需源码与实际加载确认，不将存在文件等同可用。
- 第二候选：Unsloth `gemma-4-26B-A4B-it-UD-Q3_K_M.gguf`，12,728,497,888 bytes；SHA-256 `811882f6df81c8ea204a5d382f196d6bd601245091786912d4c70df41cdfa052`。

文件大小和 SHA 来自对应 Hugging Face 仓库 API。下载走 q4 可访问的 IPv4 镜像分段请求，最终按官方文件 SHA 验证。下载目录与执行脚本目录分离，生成代码不得接触服务凭据。

## 测速方法

1. 使用与基线相同的 q4、GPU、llama-server 二进制和端口；初始保持 GPU layers99、Flash Attention on、K/V q4_0、batch512/ubatch128。若引擎不支持某组合，记录失败，不暗中缩短上下文、减少输入或改用 CPU 卸载后宣称同条件通过。
2. 每个模型调用自己的 `/apply-template` 与 `/tokenize`，关闭思考模式，使用同一合成 Rust 记录语料，构造严格 73,728 tokens 的模型原生输入；不复用 Qwen 的 ChatML 或 token ID。不同 tokenizer 的输入哈希不要求相同，字符覆盖范围可不同。
3. 正式请求固定生成 512 tokens、temperature0、seed42、ignore_eos=true。保存服务端完整 timings、实际缓存命中、实际 prefill、输出计数、截断标志、客户端首个非空输出和总墙钟、请求前后 GPU 状态。
4. 三轮依次测试：重启后的首推理请求且无输入 KV；热 GPU 但不复用 KV；预热 65,536 输入前缀后追加至 73,728；完整输入重复。冷测临时屏蔽已有 HTTP 启动预热，结束恢复配置；不清 OS 文件缓存，不包含模型加载耗时。
5. 缓存数使用 `timings.cache_n`，求值数使用 `timings.prompt_n`；实际行为如实记录，不能把预期命中当成实际命中。完整重复只重算少量 tokens 时，不将有效输入速率当成长输入 prefill 算力。
6. MTP 独立记录加载参数、draft/accepted 数量、服务端计时与完整墙钟；主模型/输入等保持一致。以端到端吞吐判断收益，不只看草稿接受率。

## 能力检查

- 聊天、旧 alias 兼容但实际响应模型正确、强制工具调用、工具结果往返、JSON 输出。工具往返加入在首次调用后生成的随机回执，并核对结果与回执，确认工具消息确实被读取。
- 两项小型代码修改任务，覆盖边界条件。保留模型生成源码与已知固定测试，用临时无网络、只读文件系统、无凭据挂载、受限 CPU/内存/PID 的容器执行。
- 恢复 Qwen 后使用相同的两项代码题补充能力对照，不重复既有 Qwen 吞吐基准。候选源码另做人工审阅，确认固定测试结果对应实际函数实现。
- 检查是小型验收，不等同 SWE-bench、复杂仓库修复质量或96K检索质量评测。尚未实际执行的用例标为未运行，不能计为通过。

## 服务与恢复

- 实际发出鉴权请求时由脚本在进程内读取既有 key，不显示、不复制到报告。
- 切换前备份当前服务 unit、override 和身份清单；确认单槽空闲，先停止旧容器再安装新配置。
- 加载或运行失败后恢复 Qwen，并实际验证服务 active、正确模型与98,304单槽。保留所有模型文件、分段与配置备份，不清理用户数据。
- 最终交付 JSON 原始记录、Markdown 对比、备份位置和具体恢复命令；不提交、打 tag 或推送 Git。

本文件记录已授权方案。执行已完成：12B QAT、12B QAT + MTP n2、26B-A4B Q3 均完成四条件各三轮，共 36 个正式 Gemma 性能样本；三个配置均未通过金额题完整验收。26B 结束后已恢复 Qwen3.6-35B-A3B，并通过本地及公网鉴权请求验证。最终结果、限制、失败用例和恢复证据见[完整报告](README.md)及[机器可读对照](comparison.json)。
