# 0.141.0-rc3：后台 supervisor PID 就绪读取验收

日期：2026-11-04。基线：默认分支 `develop` 的 `9960225b5a3989674f82651d26ace4955fe4b01e`。

## 原始失败与原因

[Windows 原始 CI](https://github.com/niuwoai/willdeep-cli/actions/runs/41751631277/job/126317835581) 的 `headless_runtime` 为 32 passed、1 failed。`background_supervisor_completes_work_and_kills_it_when_parent_disconnects` 在原第 78 行读取 PID 文件时收到 `Os { code: 32, kind: Uncategorized }`，表示文件仍被写入进程占用。该文件上一条修改提交为 `f8aea922f4127dc9df53ea278e540f756471d9aa`。

原夹具只等待文件存在，然后立即读取、解析。文件创建早于写入完成及句柄释放；仅重试解析也可能把数字前缀误当成完整 PID。

## 本次改动

- 用同一个 5 秒截止时间等待文件可读、具有完整 LF/CRLF 行结束标记且能解析为非零 `u32`。
- Unix 夹具追加 LF；Windows `Set-Content` 使用 ASCII 和默认行结束符，取消 `-NoNewline`。
- 文件缺失、sharing violation、未完成写入及无效 PID 都在截止时间内重试，到期返回最后一次真实错误。
- 失败时释放 liveness stdin，等待 supervisor 正常处理断连，再报告 PID 路径、等待时长、读取错误（含原生错误码）、退出状态、stdout/stderr 及目录清理结果。
- 保留完整任务结果、有效 PID 证明、断连后 5 秒内退出、`status=killed` 和 Unix 子进程消失断言。
- 回归覆盖 LF/CRLF、空及不完整数据、数字前缀、无效字符、零、溢出、符号、多余空白和多行；读回调确定性推进缺失→空→数字前缀→完整记录，验证必须经过全部状态。
- Windows 专属回归通过 `OpenOptionsExt::share_mode(0)` 制造真实 error 32；读者实际观测到错误后才通知写者释放句柄，随后重试成功。

运行时、API 和架构契约无变更。版本清单与当前文档同步为 `0.141.0-rc3`，Cargo.lock 由 Cargo 更新，仅变更四个本地包版本。
