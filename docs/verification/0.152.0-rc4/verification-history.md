# 0.152.0-rc4 验收过程与失败记录

日期：2026-11-17。本文件保留开发过程中的失败，不以最终通过覆盖历史。最终应用身份及覆盖范围以同目录的交付记录为准。

- 第一轮 TUI 原生回归：665 通过、4 失败、2 忽略。运行期间撤回了显式本地队列的符号改动，并修正 Held 回执的旧文字断言；该次测试不能作为最终源码的通过证据。
- 新增完整统计行回归最初误把生成的轮次统计当作可复制正文，断言预期统计全文，实际为空。统计原本就排除在正文复制之外，测试已改为保留这个边界；真实复制另外选择用户原文并精确比对。
- 后续原生回归的统计单元格比较仍失败。诊断表明夹具关闭了 compact 常驻状态栏，拖选生成反馈后视口减少一行，原统计已在视口之外，测试却继续读取旧屏幕行。改用来源坐标定位，并在这项完整统计行比较中使用正常常驻状态栏；既有隐藏状态栏、阅读锚点和缩放回归仍保留。未据此改动 Runtime 或统计生成逻辑。
- 第一次严格整行 PTY 回归误将 compact 输入框两端的既有 `▔` 边框判为残字。见 [失败报告](tui-interactions/integration.json)。修正边框识别后，继续要求提示文本及尾部空白完整匹配，18 项通过，见 [第一份通过报告](tui-interactions-final/integration.json)。
- 状态符号 PTY 第一轮 compact 中英两种语言通过；full 的鼠标起点误取聊天框左边框，未进入正文选择，因此回看提示等待超时，见 [失败报告](status-symbols-attempt1/status-symbols.json)。修正起点为正文范围后，两布局、中英两种语言共 28 项通过，见 [第一份通过报告](status-symbols-final/status-symbols.json)。
- 第一份优化应用 SHA256 为 `19e0aa9b5d05c889f23f45b2be01ae793e3bfa242792e78abecf419139a25c3f`，同时通过队列时序 10 项。检查真实画面后发现活动区和底栏仍重复显示普通完成短句，因此继续统一为符号，并对最终优化应用重新验收；前述应用不冒充最终安装产物。

- 最终应用的首轮流式交互检查有 16 项通过，full 的返回最新点击超时，见[失败报告](tui-interactions-final2/integration.json)。夹具在第二轮结束后固定等待 0.5 秒即取坐标，保存帧显示 full 活动区在运行与结束时相差 3 行；点击可能使用仍在缓冲中的旧运行帧。夹具已改为等待第二条回复持久化，再等待完成边界之后的完整终端帧，从该帧定位提示后只点击一次；仍严格要求显示第二条回复、保留原草稿且 Provider 请求数精确为 2。未以重试点击、放宽正文断言或改动产品逻辑掩盖失败；修正后同一最终应用 18 项完整通过，见[最终交互报告](tui-interactions-final3/integration.json)。最终状态符号 28 项、队列时序 10 项也通过，三份报告均绑定 SHA256 `a776238e14831a97592c56704e3d56945ddb6500ea48ad0fde1eb99ac7511e44`。

完整 ANSI、逐帧 cells JSON 和所有中间 SVG 留在本地验收目录；仓库提交机器可读报告及选定的实际终端画面，避免重复提交大量逐帧数据。所有 PTY 仅连接回环合成 Provider，使用私有 HOME/工作区；OSC 52 只由夹具捕获，不转发真实剪贴板。
