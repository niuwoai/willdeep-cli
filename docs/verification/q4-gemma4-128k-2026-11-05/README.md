# q4：Gemma 4 12B QAT + MTP，128K单路与双路实测

结论：针对本次重点验证的72K—124K长输入、希望一个子任务尽快完成的场景，推荐**单路、每槽128K**。q4已切回该配置常驻，本地与公网健康、鉴权模型列表和聊天于2026-11-04T18:57:27Z通过最终复核。固定接口与代码验收共14项，13项通过、金额题1项失败（7/9个测试方法通过），没有隐去该模型能力限制。

完整机器可读结果见 [comparison.json](comparison.json)，所有正式原始请求、响应、SSE及验收证据保存在`raw/`。

双路适合多个8K短任务追求总吞吐的场景：本轮两个8K请求的端到端总输出吞吐提高约21.7%。72K与124K时，双路没有带来明显的总完成时间收益，并显著推迟了首个任务完成；它也没有让只有一个活动请求时的速度明显改善。

每个客户端使用等长但正文不同的A/B提示，各输出512 tokens。单路真实排队，双路分别绑定槽0/1；全部无KV复用。起点是两客户端的共同barrier，包含prefill、生成与排队。

双路下两个序列共享GPU。72K双路首轮原始事件中，客户端0约33.419秒收到首个内容，但其生成阶段耗时41.148秒；客户端1的prefill耗时38.046秒，两个阶段发生重叠。服务端`predicted_ms`反映该序列经历的生成阶段墙钟时间，包含资源竞争影响。因此双路下单客户端的server decode rate可能显著低于仅1路活动时的值，不能按两个独立decoder解释。

选择单路的依据是任务完成延迟：72K首个任务约39.3秒完成，而双路约74.6秒；124K约80.2秒与148.1秒。双路主要改善8K短任务的整批完成和较晚客户端的首输出，长输入总吞吐基本持平。每组仅3轮，约1%的差异不作统计显著性解释。

## 与此前96K窗口的关系

此前96K窗口、72K输入、12B QAT+MTP的热无KV结果约为prefill2221.94 tok/s、decode86.49 tok/s、首输出33.243秒。本轮128K单路、72K输入为2243.11、86.75和32.937秒，处于相近范围。

这可以作为运维观察，不能当作严格的“只改变context参数”的因果实验：两轮夹具、缓存控制和执行条件有区别。窗口允许128K也不意味着每个请求都必须填满；本轮实际输入从72K增长到124K后，无缓存首输出从约33秒增长到约72秒，decode由约87降到约68 tok/s。

## 方法、原始证据与异常轮次

正式对照只使用：

- [单路results](raw/runs/p1-128k-retry1/results.json)：36个正式请求，2026-11-04T17:41:17Z—18:08:10Z。
- [双路results](raw/runs/p2-128k-retry1/results.json)：36个正式请求，2026-11-04T18:24:35Z—18:51:33Z。
- 两组A/B token数组哈希分别一致；每组均有11份运行身份/槽位/CLI快照，所有正式请求实际输出512且无截断。
- 相同固定二进制、主权重与MTP；temperature0、seed42、ignore_eos；本机127.0.0.1测速，避免将公网延迟算作引擎速度。
- Decode使用固定构建的`(predicted_n-1) / predicted_ms`；首输出是客户端首次收到非空SSE content，不是严格GPU TTFT。
- `timings.cache_n`才是输入缓存命中；顶层`tokens_cached`是生成后驻留长度，不用于计算输入命中。
- 无KV请求及前缀priming显式关闭`cache_prompt`，正式前缀复用请求再开启。日常服务的RAM/KV缓存功能没有禁用。

保留的异常轮次：

1. `p1-128k`：不同短提示未清除RAM提示快照，第二个8K请求命中8187 tokens，基准主动拒绝并停止；不进入正式结果。
2. `p2-128k`：SSH隧道中断后采集器`Errno::EPIPE`，保存25个正式样本，124K组不完整；不混入正式双路结果。随后确认模型仍为双路每槽128K且空闲。
3. 双路正式重跑通过独立transient systemd服务执行，客户端基准进程限2GiB/1 CPU；Ruby解析与记录仍在CPU上，模型容器配置未变。此方式防止SSH断线中止测试。
4. 最终切回单路后首次公网verify遇到一次`/health` HTTP404；随后本机与q4发起的实时公网健康请求均HTTP200。最终鉴权复核结果另行记录，不将单次错误隐藏为成功。

汇总器逐条读取原始request/final文件，验证SHA及内嵌响应一致性，再从native与客户端单调时钟重算统计；检查完整矩阵、每槽128K和固定模型身份，代码题失败会保留原状态。基准离线14场景/129断言通过，汇总器17场景/111断言通过；部署控制器本机及q4离线38测试/367断言通过。离线测试不能代替本轮真实API和吞吐证据。
