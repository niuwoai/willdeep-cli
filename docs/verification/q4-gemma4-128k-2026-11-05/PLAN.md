## 测试定义

- 128K = 每槽 131,072 tokens。单路总 `--ctx-size 131072 --parallel 1`；双路总 `--ctx-size 262144 --parallel 2`。必须用实际 `/slots[].n_ctx` 验证，不只看启动参数。
- 两配置均采用主权重 QAT Q4_0，MTP n-max=2，Flash Attention，K/V q4_0，batch512/ubatch128，开启 Jinja，保持相同 GPU/容器/模型版本；暂不启用 `--swa-full`。
- 正式输入长度 8,192、73,728、126,976 tokens；最高为 124K，为输出和模板留空间，不宣称已经填满 128K。每请求实际输出 512 tokens，temperature0、seed42、ignore_eos。
- 使用模型自身 chat template/tokenizer 构建输入，保存实际 token 数组和哈希；同一输入跨单双路保持一致。并发两客户端要避免可互相复用的相同长前缀影响比较；以实际 cache_n、prompt_n 为准。
- 服务已预热，测试不包含重启/权重加载，也不将其称为进程冷启动。测单个活动请求、两个同时到达的请求（单路允许排队，双路同时运行）、8K 新尾部的前缀复用；每组 3 轮。
- 同时记录 prefill/decode、首个非空输出、单请求墙钟、两请求完成的 makespan、端到端总输出吞吐和实际 MTP 草稿/接受计数。两客户端 decoder 速率之和不能冒充端到端吞吐。
- 核验实际输出512、没有截断、实际槽位、cache_n+prompt_n等于输入、真实 draft-mtp 计数。显存仅在请求前后采样，明确不是全程峰值。
- 配置加载失败、显存不足、MTP不支持多槽或并发异常均保留证据，不偷偷降上下文、关MTP或把排队冒充并行。
