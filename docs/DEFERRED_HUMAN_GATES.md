# 人工等待与独立消息调度

开发版本：Rust 0.116.0-rc1；Mac 1.424.0-rc1；Android 1.27.0-rc1。未发布。

## 已实现行为

Runtime 持久保存已提交的队列，Android、Web 和 Runtime TUI 使用同一消息 ID、附件和原文校验进行同步编辑、删除与优先处理。Web 和 TUI 收到持久化回执后才清理输入，远端队列不由客户端自动消费。客户端草稿不属于 Runtime 队列。Mac 托管会话由 Mac 执行宿主管理，队列随会话保存并向手机投影。

等待人工确认或输入时，共享 TOML 配置 `[agent]` 下的 `human_wait_yield_seconds` 默认 300；0 关闭自动让出。超时且队列非空时先收起原卡片；依赖不明确的消息继续排队，原卡片保持收起，普通输入仍可用。调度器只将明确独立的消息移入单独执行记录，跳过不明确或有依赖的队首。工具权限保持原样。可手动标记独立消息，或优先处理但继续判断依赖。编辑消息撤销其原独立标记。

Mac 交接消息时，先同步保存独立任务的正文与附件，再确认原队列移交落盘，之后才允许模型执行；失败保留原队列。原请求保留交互 ID 和恢复句柄，收起不代表批准、拒绝、回答或取消。独立任务完成后重新展示原请求并重置计时，可以反复让出。旧答案在独立任务执行期间先记录，在安全边界恢复到原请求；独立任务也需要输入时保留独立请求，不能覆盖旧卡片。停止后抑制自动恢复。

## 保守边界

自动判定不调用工具。所有未解决请求、原任务和已有独立任务历史参与判断；严格 JSON、完整输出、无阻塞项才可视为独立。上下文超过 48 KiB、附件无法完整分析、格式错误、模型超时或不明确时继续排队。分类结果绑定原请求和队列快照，状态变化后重新核对。没有队列时不调用分类模型。

Rust 独立执行使用独立核心会话与租约，展示时合并历史副本，不能将展示投影保存回原模型历史。Mac 独立执行使用隐藏的子会话与单独工具等待状态，人工等待释放服务商并发名额，恢复前重新获取。进程退出不能持久化 continuation：现有中断恢复规则继续适用，不自动重放副作用。

## 验证边界

使用隔离工作树、本地单测、Web 组件测试、Android lint 和构建、Mac 单测检查。具体执行结果以本任务测试报告为准。尚未替换安装应用或升级、重启现有 Runtime；没有把模拟快照和单元测试声明为多设备真实 UI 验收。
